## 1. Vision & Guiding Principles

Build a browser-native, serverless-by-default authoring platform for building design that matches professional CAD/BIM tools (Revit, ArchiCAD) in geometric accuracy, while reaching that parity **progressively** rather than all at once.

Non-negotiable principles for every design decision in this document:

- **Exact geometry, always.** The source of truth for any shape is B-Rep solid geometry from the kernel — never a mesh. Meshes are a display artifact, regenerated on demand.
- **Additive, not disruptive, growth.** Every release from v1.0.0 onward must be able to add a new shape type, a new tool/action, or a new file format without modifying the core engine or breaking existing projects. This is the central architectural requirement — see Section 4.
- **MVP ≠ mini-Revit.** v1.0.0 does not replicate Revit's feature set. It must be genuinely usable for a real (if simple) building-design task, end to end, using a small, well-chosen set of primitives the extensibility model can grow from.
- **100% free, zero backend.** Static hosting on Cloudflare Pages. No accounts, no servers.
- **Works offline after first load.** No network dependency is required to *use* the app once it has loaded once: a **service worker precaches the app shell and the WASM kernel** (Section 8), and all documents live locally (Section 7). First load necessarily downloads the app + kernel over the network; every subsequent use — including fully offline — is served from cache.
- **No architectural dead ends.** Nothing in v1.0.0 should have to be thrown away when v1.1.0 adds an optional multi-tenant backend and real-time collaboration. The domain model is designed against explicit long-term north-stars — see `core_logic.md`.

## 2. Technology Stack

| Layer | Technology | Rationale |
|---|---|---|
| Geometry kernel | **OpenCascade.js** (OCCT compiled to WebAssembly), **multi-threaded build + single-threaded fallback** | Industrial-grade B-Rep kernel: exact NURBS, booleans, fillets, sweeps, lofts. LGPL-2.1 — commercially safe, no royalties. OpenCascade.js ships an official multi-threading-enabled custom build (needs `SharedArrayBuffer`); the single-threaded build is the fallback (Section 8). |
| Persistent naming | **Functional / generative sub-shape naming** (via OCCT `BRepBuilderAPI_MakeShape` `Generated`/`Modified`/`IsDeleted` — core B-Rep, no OCAF/TNaming) | Sub-shape identity is *derived* from operation-DAG provenance, not *recovered* by matching, so parametric references (openings, fillets) survive rebuilds. See Section 4.5. |
| IFC interoperability | **web-ifc** (That Open Company) — **import only in v1.0.0** | web-ifc's *writer* is officially pre-alpha ("may be quick and correct, or slow and broken"). v1.0.0 therefore **reads** IFC as a codec (mapped-or-GenericSolid, Section 4.3). **IFC export + embedded-IFC-on-save are deferred to v1.0.x** behind the same codec abstraction. Target IFC4 (ADD2 TC1); mapping abstraction IFC5/IFCX-ready. |
| Rendering | **three.js**, `WebGPURenderer` (automatic WebGL 2 fallback) | Mature ecosystem, largest body of prior art for CAD-kernel and IFC browser viewers. Compute shaders unlock GPU-side culling/instancing for large models. Custom shading uses **TSL** (compiles to WGSL and GLSL), not raw GLSL, since the legacy `ShaderMaterial`/`EffectComposer` path isn't supported on the WebGPU backend. |
| App shell / UI | **TypeScript + React** | Hot path (modeling, rendering, interaction) must be JS/TS talking directly to the WASM kernel — non-negotiable for interactivity (Section 3). |
| Client persistence | **File System Access API + OPFS + IndexedDB** | No backend required; see Section 7. |
| Offline & install | **Service Worker + Web App Manifest** | Precaches app shell + versioned WASM keyed by build id so the app runs offline after first load (Section 1, Section 8). Installable PWA. |
| Hosting | **Cloudflare Pages** (static) | Matches the 100%-free, zero-backend constraint. |
| Build & tooling | **Vite + TypeScript** (app bundle) · **Python** (orchestration) | Vite/pnpm build the TS/React app; Python drives WASM build scripts, IFC schema code-gen, CI pipelines, and asset/regression pipelines. |
| Golden-value seeding (offline) | **Python + pythonocc-core / FreeCAD** | One-time, **offline** generation of trusted golden reference values (volumes, areas, topology counts) for the regression harness. **Not run in CI**; see Section 9. |
| Power-user scripting | **Python via Pyodide** (optional, sandboxed, non-hot-path) | Parametric macro/family authoring in the spirit of CadQuery/build123d, exposed as a scripting console — not part of the interactive modeling loop, ships after MVP. See Section 10. |
| Future backend (v1.1.0+, not built now) | **Python (FastAPI)** | Chosen now only so v1.0.0 tooling and the future backend share one language across non-hot-path parts of the stack. |

**Explicitly not in the hot path:** Python, Pyodide, or any interpreted runtime. Real-time dragging/editing of geometry stays in TS ↔ WASM with no extra marshaling layer. Note the interactivity boundary in Section 3 (edit coalescing) — "real-time" applies to viewport manipulation always, and to geometric rebuild subject to a debounce/cancellation budget.

## 3. Process & Threading Architecture

```
Main thread                         Geometry Worker                 Optional: Macro Worker
─────────────                       ────────────────                ──────────────────────
UI (React)                          OpenCascade.js (OCCT WASM)      Pyodide (lazy-loaded,
Scene graph (three.js)     <──────  Command executor                only if macro panel
Command dispatcher          msg     Persistent-naming resolver       is opened by the user —
Undo/redo stack             ────>   Tessellation (mesh + provenance) post-MVP, Section 10)
Persistence manager                 IFC read (web-ifc)
Service worker (cache)              Operation-failure marshaller
```

- The geometry kernel **always** runs in a dedicated Web Worker, communicating via `postMessage` with transferable `ArrayBuffer`s. This keeps the UI thread responsive during expensive boolean/fillet operations regardless of model complexity.
- The kernel worker's public API is a **flat, versioned message protocol** (not a live object reference) so it can later be swapped, upgraded, or moved server-side in a future edition without touching the UI layer. This is the seam that keeps the future **headless/server-side kernel** north-star (`core_logic.md`) open.
- **Tessellation carries sub-shape provenance.** Every mesh buffer the worker emits includes a **provenance channel**: a per-triangle → face `SubShapeRef` map and per-edge-polyline → edge `SubShapeRef` map (Section 4.5). This is what makes viewport **sub-shape picking** (select a face/edge) able to return a stable `SubShapeRef` — the *input* side of the naming system. It is part of the frozen kernel protocol (Section 12).
- The persistent-naming resolver (Section 4.5) lives inside the geometry worker, alongside the kernel: it consumes the kernel's `Generated`/`Modified`/`IsDeleted` maker maps in TypeScript today, with a possible future C++ shim for performance. The worker protocol is kept engine-agnostic so that move requires no UI change.
- **Edit coalescing / interactivity budget.** Rapid parameter edits (e.g. dragging a slider or a handle) are **debounced and coalesced**, and an in-flight kernel operation superseded by a newer edit is **cancelled or its result discarded**. OCCT operations are not interruptible mid-call, so the dispatcher must drop stale results rather than block. Viewport camera manipulation never waits on the kernel.
- Pyodide (if/when the macro console is used) runs in its own worker, isolated from the modeling hot path, and is lazy-loaded only on first use so it never affects baseline load time.

## 4. Core Extensibility Architecture (the central requirement)

This section answers "the MVP must be 100% scalable through the 1.0.x line until it reaches Revit parity." **Five** registries/subsystems make this possible. Every future feature is an addition to one of these, never a change to the core. The full contracts and their interaction are documented in `architecture.md`; this section is the normative summary.

### 4.1 BIM Object Type Registry

Every modeled thing (wall, slab, door, column, eventually roof, curtain wall, stair, MEP run…) is a BIM Object Type implementing one shared contract:

```ts
interface BimObjectType<Params> {
  typeId: string;                       // e.g. "core.wall.v1"
  defaultParams(): Params;
  buildGeometry(params: Params, ctx: KernelContext): BuildResult; // calls the OCCT worker; may fail (Section 6.4)
  parameterSchema: ParamSchema;         // drives auto-generated property panel UI
  ifcMapping: IfcClassMapping;          // how this maps to/from IFC on import (export: v1.0.x)
  quantities?: QuantityMapping;         // typed quantities for future analysis/schedules (north-star)
  version: number;                      // for migrating saved projects as the type evolves
}
```

- New types are registered — the core scene graph, persistence format, and undo system never need the concrete list of types in advance.
- `version` + a per-type migration function keeps a v1.0.0 project file loadable after the Wall type gains new parameters in v1.0.4.
- `buildGeometry` returns a `BuildResult` (success with a `ShapeHandle`, or a typed failure — Section 6.4), never throwing across the worker boundary.
- The optional `quantities` field is declared now (a no-op consumer in v1.0.0) so the **analysis & quantities** north-star (`core_logic.md`) does not require a contract change later.
- MVP ships a small number of these (Section 5); everything after v1.0.0 is a new entry.

### 4.2 Command / Action Registry

Every user-facing action (draw line, extrude, boolean subtract, move, array, dimension…) implements:

```ts
interface Command {
  commandId: string;
  execute(ctx: DocumentContext, args: CommandArgs): CommandResult; // UndoableEdit on success; typed failure otherwise
  contributesUI?: RibbonContribution;   // optional: where it appears in the toolbar/ribbon
}
```

- The undo/redo stack operates purely on `UndoableEdit` objects, not command internals — adding commands never touches the undo system.
- A command whose kernel work fails returns a **failure** and produces **no** `UndoableEdit` (Section 6.4).
- The ribbon/toolbar is **generated** from the registry, not hand-wired — a new command appears purely by registering it with a `contributesUI` descriptor.

### 4.3 File Format Codec Registry

Import/export formats are registered as independent codecs against one interface (`Importer` / `Exporter`), decoupled from the BIM Object Type Registry via the `ifcMapping` field. Adding a format is additive.

- **v1.0.0 ships the IFC *importer*** (web-ifc) only; the IFC *exporter* is a sibling registration deferred to v1.0.x (Section 2, decision D3).
- The IFC codec's schema binding is abstracted (`IfcSchemaVersion`) so an IFC5/IFCX codec — and later STEP, DXF, glTF — are sibling registrations, not rewrites.

### 4.4 View / Representation Registry

3D view, 2D plan-cut view, 2D elevation, and (future) schedules/sheets are all "representations" of the same underlying document graph, registered independently, so 2D drafting and (north-star) quantity schedules can be added later without touching the 3D authoring core.

### 4.5 Persistent Naming Subsystem *(decision D1)*

**Problem.** When an `Opening` subtracts from a `Wall`, or a `fillet` is applied to an edge, that reference must survive a **rebuild** after the host's parameters change. OCCT booleans do **not** guarantee stable face/edge identity across regeneration. This is the "topological naming problem" that has historically plagued parametric CAD (e.g. FreeCAD). The validated decision is to solve it **from day 1** with a **functional (generative) naming** model rather than the a-posteriori geometric matching most open-source CAD relies on.

**Approach — functional / generative naming.**

- Identity is **assigned at creation and carried forward**, never recovered after the fact. A sub-shape's identity **is its derivation**: the operation that produced it plus the identities of the inputs that produced it (e.g. "the face generated by `Fillet(op#7)` acting on `Edge{generated by Extrude(op#3), role=lateral, k=2}`"). Because the identity is a structural path, it is immutable by construction.
- Propagation uses OCCT's `BRepBuilderAPI_MakeShape` maker interface — `Generated()` / `Modified()` / `IsDeleted()` — which is **core B-Rep and present in the OpenCascade.js build** (no OCAF/TNaming dependency). Each operation labels its outputs from its inputs as it builds; there is **no geometric guessing on the resolve path**.
- Every sub-shape reference stored in `scene.json` is an **opaque, stable `SubShapeRef`** — a structured path (`nodeId` + `role` + `occurrence`) through the operation graph, never a raw OCCT index. `SubShapeRef` is an interface; its encoding may evolve within the `1.0.x` line via the same per-type/version migration mechanism as Section 4.1.
- **Hybrid graph granularity.** The operation graph is coarse-grained (feature-level) for the UI and model history, and fine-grained (primitive-op level) for internal topological propagation. References resolve against the fine layer; the user sees the coarse layer.

**Honest dependency on OCCT history quality (2026-07-08).** Verified against OCCT documentation and the FreeCAD topological-naming literature: `BRepBuilderAPI_MakeShape` history is **robust for faces** but historically **weakest for edges and vertices** generated by boolean section curves, and *not all maker classes expose the same interface*. The resolver's hardest case is exactly chaining a fillet onto an edge produced by a boolean. Mitigations, all normative:
- v1.0.0 constrains itself to operations whose `Generated`/`Modified` **edge/vertex** coverage is verified during Phase 2 (the persistent-naming regression suite, Section 9, is the gate). An operation whose history is inadequate for a needed reference is either wrapped to reconstruct the missing history explicitly, or its reference class is deferred — it does **not** silently fall back to geometric guessing.
- The **fallback contract**, if the general resolver proves too costly early: constrain the *very first* internal milestone to purely positional openings and non-persisted fillets, but ship v1.0.0 only once `SubShapeRef` is real — retrofitting it later would break `scene.json` and violate the "no dead ends" principle.

**Splits, merges, and determinism.**

- When a parameter change makes one sub-shape split into many (or merge), the maker interface returns a 1→N (or N→1) map. Children are ordered by a **structural tie-break**: the identities of the tool/input entities that caused the split (pure graph data, no geometry). Each operation type defines its ordering rule.
- For a **genuinely symmetric** split where structural data cannot break the tie (e.g. mirrored openings), a single **bounded positional key** (centroid rounded to the mm grid, lexicographic) is the *sole* sanctioned last resort — the only place geometry touches the resolve path. See Section 6.5 for the cross-machine determinism rules this key must obey.
- OCCT booleans run **multi-threaded** for performance (decision D8); to keep identity deterministic, each operation's `Generated`/`Modified` output is passed through a **canonical re-sort** (the structural tie-break above) **before** IDs are assigned, so thread-ordering nondeterminism is normalized away.

**Rebuild, load, and broken references.**

- The identity **token map** is persisted in `scene.json`. On an edit, only the affected subgraph is rebuilt and identities are re-propagated (incremental rebuild). On load, deterministic replay re-binds the stored tokens to concrete OCCT entities.
- On rebuild, each `SubShapeRef` is re-resolved along its derivation path. If a reference becomes **unresolvable** (the host was edited so the referenced sub-shape no longer exists), the dependent feature is marked **broken** and surfaced in the UI for **manual retargeting** — it is **never** silently reattached to a different element.

**Risk (recorded honestly).** This remains the single hardest engineering item in v1.0.0 and can dominate the timeline. It is on the critical path for parametric `Opening` and `fillet`/`chamfer`. It is materially de-risked versus the draft by depending only on the **core maker interface** (no unverified OCAF/TNaming binding) — but the edge/vertex-history caveat above is the residual risk to watch.

**Why this matters concretely:** shipping "add a Door type" or "add a Fillet command" in v1.0.3 should be an additive PR against a registry — not a cross-cutting change. This is what keeps parallel work conflict-free in the core.

## 5. MVP Definition — v1.0.0

The MVP is deliberately **not** a small Revit. It is a small number of primitives and actions chosen because the extensibility model (Section 4) grows directly from them with no rework.

### 5.1 BIM Object Types (v1.0.0)

| Type | Notes |
|---|---|
| **Wall** | Straight, constant-height, constant-thickness. OCCT extrude + boolean. |
| **Slab / Floor** | Planar boundary + thickness extrude. |
| **Column** | Simple profile (rect/circular) extrude. |
| **Opening** | Boolean-subtracted void in a Wall or Slab, referencing its host via a `SubShapeRef` (Section 4.5). Carries an **anchoring parameter** — `fixed` (absolute offset from a datum edge/corner, the v1.0.0 default), `proportional`, or `centered` — that defines how it repositions when the host is resized (decision D12; domain rationale in `core_logic.md`). The same mechanism will later host real Door/Window types as "Opening + inserted family." |
| **GenericSolid** | Free sketch + extrude/revolve — the escape hatch that keeps the MVP useful for shapes not yet modeled as a named BIM type, and the import target for unmapped IFC (Section 4.3). |
| **Level / Story** | Organizes objects by elevation; required scaffolding for everything BIM-shaped that follows. |

### 5.2 Actions (v1.0.0)

- **2D sketching:** line, rectangle, circle, arc, dimension entry (numeric input, **not** full geometric constraint solving yet). Sketches are **validated** (closed, non-self-intersecting) before being handed to extrude/revolve.
- **Extrude**, **boolean** (union/subtract/intersect), **fillet/chamfer** edge (persisted via `SubShapeRef`).
- **Move, rotate, copy, array** (linear/grid).
- **Level management**, object-to-level assignment.
- **Section-cut-based 2D views** — a plan view **and one elevation** — generated from the 3D model as real cuts of the real geometry (itself a proof that the kernel is the source of truth), **not** a separate drafting engine.
- **IFC import** (mapped-or-GenericSolid). *IFC export is v1.0.x.*
- **Save / Open** (local `.bimproj`, Section 7).

### 5.3 Explicit non-goals for v1.0.0

Deferred to later 1.0.x releases (all additive registry entries — none require a v1.0.0 redesign): **IFC export & embedded-IFC-on-save** (blocked on web-ifc writer maturity, decision D3); geometry **auto-repair** of failed operations (Section 6.4); a real geometric **constraint solver**; curtain walls; roofs beyond a flat/single-slope slab; stairs/railings as parametric families; MEP routing; schedules/quantities; sheet/print layout; rendering materials/lighting beyond basic shading; the Pyodide **macro console**; multi-user real-time co-editing; cloud storage; code-compliance checking.

## 6. Data Model & File Format

Project files are a single `.bimproj` package (a zip), so "save locally, re-import later" works with zero backend:

```
project.bimproj (zip)
├── manifest.json         # app version, schema version, OCCT/OpenCascade.js build id,
│                         #   list of BIM object type versions used
├── scene.json            # parametric object graph + persisted naming token map:
│                         #   {id, typeId, params, levelId, transform, subShapeRefs[]}
│                         #   plus the operation-DAG identity tokens (Section 4.5)
├── geometry-cache.brep   # OCCT-native cached B-Rep, to avoid full rebuild on load
├── history.json          # command/undo history (optional, for session continuity)
└── thumbnail.png         # generated on save from the active 3D view (Section 6.6)
                          # (v1.0.x adds export.ifc — deferred, decision D3)
```

- **Units & precision.** All geometry is authored and stored in **millimeters** (project internal unit), double precision. IFC declares the corresponding `IfcSIUnit` (`MILLI`, `METRE`); the mm grid is also the rounding basis for the Section 4.5 positional last-resort tie-break. Large-coordinate robustness is addressed in Section 6.5.
- `scene.json` is the **editable parametric truth**; `geometry-cache.brep` is a performance cache, rebuildable from `scene.json` if missing or stale (a corrupted cache never loses the actual design).
- `manifest.json`'s per-type version list drives the Section 4.1 migration mechanism on load. The recorded **OCCT/OpenCascade.js build id** guards BREP-cache compatibility: if the loading app's kernel build differs, the cache is treated as stale and rebuilt.
- `scene.json` sub-shape references are opaque `SubShapeRef`s (Section 4.5), never raw OCCT indices.

### 6.1 Undo/redo semantics (decision D-fold)

The undo stack is a stack of `UndoableEdit` **state deltas**, not a blind command replay. Because sub-shape references are stable (`SubShapeRef`) and geometry is deterministically rebuildable from `scene.json`, undo restores the prior parametric state and re-resolves references, avoiding the "replay + nondeterministic boolean topology" hazard. Undo/redo may therefore trigger an incremental kernel rebuild of the affected subgraph (not O(1)); it participates in the same edit-coalescing budget as Section 3. `history.json` persists this stack for session continuity only; it is optional and never the source of truth. Manual retargeting of a broken reference (Section 4.5) is itself an `UndoableEdit`.

### 6.2 `ShapeHandle` lifecycle & WASM memory management *(new 2026-07-08)*

OpenCascade.js objects live on the Emscripten heap and are **not** garbage-collected by JS — each `TopoDS_Shape` and intermediate must be explicitly released. Left unmanaged, a long editing session leaks WASM memory until the tab OOMs. Normative rules:

- A `ShapeHandle` is an opaque token owned by the worker; the main thread never holds raw OCCT pointers.
- The worker maintains an explicit **handle registry** with deterministic ownership: handles referenced by the live document graph or the persisted BREP cache are retained; all intermediates from a rebuild are freed at the end of that rebuild.
- Superseded geometry from a coalesced/cancelled edit (Section 3) is freed when its result is discarded.
- The worker exposes heap-usage telemetry to the app so a soft budget can warn before exhaustion (Section 8).

### 6.4 Operation-failure contract *(new 2026-07-08, decision D10)*

OCCT operations fail routinely on legitimate user input — a fillet radius larger than the adjacent geometry, a self-intersecting or open profile, a boolean that yields an empty/invalid shape, or an internal `Standard_Failure`. v1.0.0 behavior is specified, not left to chance:

- **Safe marshalling.** The worker wraps every kernel call so an OCCT C++ exception (`Standard_Failure`) or an invalid-result check is caught and returned as a **structured, typed failure** across the message protocol — it never crashes the WASM instance or the tab.
- **Reject + keep last-good.** A failed operation produces **no** `UndoableEdit`; the document remains at its last valid state. The user sees a typed, dismissible error explaining what failed (e.g. "fillet radius too large for edge").
- **No silent geometry.** v1.0.0 does **not** attempt auto-repair (`ShapeFix`, tolerance relaxation, retry). Auto-repair is a **flagged v1.0.x** refinement, as is a **downloadable repro bundle** (`scene.json` + the failing op) for field diagnostics — both are recorded as deferred work items here so they are not forgotten (there is no backend telemetry channel, so the repro bundle is the intended field-diagnostics path).

### 6.5 Cross-machine & large-coordinate determinism *(new 2026-07-08)*

The two build actors run different OCCT builds on different hardware (Section 12), and CI checks values seeded elsewhere. Determinism rules:

- **Structural IDs are floating-point-free.** The adjacency-graph hash (Section 9) is computed over structural `SubShapeRef` strings, so it is reproducible across machines by construction.
- **The positional tie-break is the only FP-sensitive identity path.** Its mm-grid rounding must use a fixed rounding mode and a grid coarse enough that legitimately distinct symmetric sub-shapes never collide; the golden-seeding environment is **pinned** (documented OCCT build + platform) so the seeded keys are reproducible. If two distinct sub-shapes round to the same key, that is a modelling-determinism defect surfaced by the naming regression suite, not silently tolerated.
- **Large coordinates.** Buildings modelled in mm produce large coordinate magnitudes (a 100 m span = 100 000 mm) against OCCT's default linear tolerance, which can stress boolean robustness for fine (mm-scale) features on large models. v1.0.0 documents a working-precision policy and the naming/golden suites include at least one large-extent model to catch regressions.

### 6.6 Thumbnails

`thumbnail.png` is generated on explicit save by rendering the active 3D view offscreen at a fixed small resolution; it is a convenience artifact only and never affects load.

## 7. Persistence Architecture (no backend)

| Mechanism | Purpose | Browser support |
|---|---|---|
| **File System Access API** (`showSaveFilePicker`/`createWritable`) | Primary Save / Save As to a real local file, with a stored handle for silent re-save **within the same session** | Chrome/Edge (Chromium) |
| **Zip-blob download + `<input type=file>` import** | Universal fallback Save As / Open, works everywhere | All browsers |
| **OPFS** (Origin Private File System) | Fast local scratch storage for the geometry cache during a session | All modern browsers |
| **IndexedDB** | Autosave snapshots, undo-history persistence, app settings, stored file handles | All modern browsers |
| **Service Worker Cache Storage** | Offline precache of app shell + WASM kernel (Section 8) | All modern browsers |

- **Save-handle permission reality (2026-07-08 correction).** A stored File System Access handle allows silent re-save **within a session**. **After a page reload the browser requires a user gesture to re-grant write permission** (`queryPermission`/`requestPermission` return `prompt`). The UX is therefore a one-click "resume saving to *file*" affordance on the next session, not truly silent cross-session writes. The universal download/upload fallback has no such restriction but is not silent.
- **Autosave.** Autosave writes a lightweight snapshot — `scene.json` + `geometry-cache.brep` only — to OPFS/IndexedDB on an interval **and** after every *N* undoable edits, independent of whether an explicit save file is open. Snapshots are kept as a **capped ring** (the most recent ~5, oldest dropped), and the app requests `navigator.storage.persist()` so this crash-recovery layer resists browser eviction.

## 8. Deployment, Offline & Load Budget

- **Cloudflare Pages**, static output only, for v1.0.0.
- A `_headers` file sets `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` to unlock `SharedArrayBuffer`, enabling the **multi-threaded** OCCT WASM build.
- **Single-threaded fallback (folded in):** the app detects when `SharedArrayBuffer` / cross-origin isolation is unavailable (some embedded, enterprise, or cross-origin-embedded contexts block it) and loads a **single-threaded** OCCT WASM build with a visible "reduced performance" notice, rather than failing to start.
- WASM assets served with correct `application/wasm` MIME type (Cloudflare Pages default) and preloaded/streamed to minimize first-load latency.
- All cross-origin assets (WASM, fonts, sample models) must be served **CORP-compatible** (`Cross-Origin-Resource-Policy`) or same-origin, since `COEP: require-corp` otherwise blocks them.
- **Offline & PWA (new 2026-07-08).** A **service worker** precaches the app shell and the (multi-MB) WASM kernel, keyed by the OCCT/OpenCascade.js **build id** so a new release invalidates the cache atomically; a **Web App Manifest** makes the app installable. This is what backs the Section 1 "works offline after first load" principle. The service worker must cache both the multi-threaded and single-threaded WASM artifacts (or fetch-and-cache the chosen one on first successful boot).
- **First-load & size budget (new 2026-07-08).** Because the two WASM builds are large, v1.0.0 sets an explicit **first-load size and time budget** (measured in CI on a throttled profile) and uses streaming compilation, preloading, and code-splitting to meet it. Exceeding the budget blocks release (Section 9).

## 9. Quality & Testing Strategy

- **Golden-snapshot + invariant harness — split into independent oracle vs. regression (2026-07-08 reframing, decision D9).** Every BIM Object Type's `buildGeometry` is gated in CI against the WASM build only (no pythonocc-core in CI). The checks are explicitly tiered by what they can and cannot certify:
  1. **Independent oracle (first-correctness).** Gross **volume / area / length** values are seeded **offline from pythonocc-core/FreeCAD** and compared within tolerance. Because these come from an independent kernel, they certify the geometry is *actually* right, not merely unchanged.
  2. **Independent topology cross-check (first-correctness).** Solid / face / edge **counts** per feature are cross-checked against the same independent tools — the coarse structural truth pythonocc *can* produce.
  3. **Regression snapshots (no-regression only).** The **per-sub-shape mass checksums** (iterated over the naming engine's token map) and the **adjacency-graph hash** (topology graph, nodes labelled by structural `SubShapeRef` IDs, serialized canonically, SHA-256) are **self-snapshotted from Bunyan's own engine** — pythonocc cannot produce structural-ID labels. These are honestly documented as guarding against *regression*, not first-correctness; the first-correctness guarantee for structure comes from checks 1–2 plus manual review at seed time.
  4. **Bounds.** Each feature's tight `Bnd_Box` (via `BRepBndLib::AddOptimal`) is checked against an explicit bounds schema.
  The harness also asserts **`SubShapeRef` resolution stability** across parameter changes.
- **Golden seeding + re-seed rule.** Golden values are generated **once, offline**, from pythonocc-core/FreeCAD on a **pinned environment** (Section 6.5), then committed. **A new or changed `buildGeometry` MUST ship with re-seeded goldens — CI fails a build that adds geometry without them.** This gate is explicit so headless agents don't miss it.
- **Persistent-naming regression suite.** A dedicated corpus of "edit host, verify dependents re-resolve or correctly break" scenarios — the highest-risk subsystem, and the **gate that validates OCCT edge/vertex history coverage** (Section 4.5). This same corpus is the **reference-stability corpus** replayed by the **kernel-migration gate**: a build that upgrades OCCT within the 1.0.x line fails if any reference re-resolves differently.
- **IFC import-fidelity corpus (export deferred).** A growing library of `.ifc` sample files (seeded from web-ifc's public test model library) plus Bunyan-authored `.bimproj` files, run through **import + mapped-or-GenericSolid** fidelity checks on every CI build. **Full IFC export round-trip is a v1.0.x gate**, not v1.0.0 (decision D3).
- **Command-level unit tests.** Every Command in the registry (Section 4.2) has isolated tests against a mock `DocumentContext`, independent of the UI, including a **failure-path test** (Section 6.4).
- **Operation-failure tests.** Known-failing operations (over-large fillet, open profile, empty boolean) must surface a typed failure and leave the document at last-good state — no crash, no partial edit.
- **Import hardening tests.** Malformed / hostile `.bimproj` (zip) and IFC inputs — decompression size/ratio caps, entry-count limits, schema validation, worker-timeout parsing — must fail safe without hanging or OOM-ing the tab. The `geometry-cache.brep` deserialization path is treated as untrusted input on load.
- **Visual regression** against both WebGPU and WebGL2 backends (from the first phase that produces pixels — resolves O5).
- **First-load budget check** (Section 8) runs in CI on a throttled profile and blocks release on regression.

## 12. Build Model & Actor Structure

The real v1.0.0 build is executed by **one human architect + two Claude Code agents**, each mapped to the environment that best fits its work:

| Actor | Environment | Primary ownership |
|---|---|---|
| **Human architect** (you) | — | Registry contracts & spec ownership; MVP scope calls; AEC/domain correctness (type & parameter semantics, IFC mapping validation); cross-cutting review and merge arbitration; final release scope. |
| **Amer** (Claude Code agent) | **Local PC** (browser available for real rendering/interaction testing) | The **browser hot path**: three.js / WebGPURenderer scene, tessellation-to-mesh pipeline (consuming the worker's provenance channel), section-cut views, TSL materials; React app shell, ribbon generation from registries, property panels; Command/interaction registry, undo/redo, input handling; File System Access / OPFS / IndexedDB persistence, `.bimproj`, **service worker/PWA**. Owns anything that must be *seen* running in a real browser. |
| **Zayd** (Claude Code agent) | **Hetzner CX23 dev box** (headless, Linux, CI-grade) | The **headless / kernel / tooling** side: OCCT WASM build (multi-threaded + single-threaded) & kernel worker API; Python build orchestration; the **geometry regression harness** (golden snapshots + invariants; offline pythonocc-core/FreeCAD seeding on the pinned env); persistent-naming resolver & regression corpus; **IFC importer** integration; DevOps / Cloudflare Pages release pipeline and versioning. Owns anything that runs best on a Linux box with no display. |

**Coordination contract.** The five registries/subsystems in Section 4 are the seams between actors. **Critical-path note (2026-07-08):** the pre-freeze path P1→P2→P3 is Zayd-heavy and largely serial. To avoid Amer idling, Amer builds the P4 shell against a **kernel mock/fake worker** implementing the protocol before P2's real kernel lands. Contract-freeze timing is **split** (decision D13): the flat message protocol freezes at end of P3 to unblock parallel work; the `BimObjectType` / `Command` / `SubShapeRef` contracts stay **release-candidate** until Wall + Opening validate them early in P5, then freeze. The human architect owns the interface definitions and any change to them.

| **D5** | Internal units & precision? | **Millimeters**, double precision (Section 6); IFC declares `IfcSIUnit` `MILLI`/`METRE`. Large-coordinate policy in Section 6.5. |
| **D6** | Geometry verification strategy? | **Golden snapshots + invariants in CI; pythonocc dropped from CI** (offline one-time seeding only) + re-seed CI gate (Section 9). Refined by **D9**. |
| **D7** | OCCT kernel upgrades within v1.0.x? | **Allowed only behind a migration gate** that replays the reference-stability corpus and fails on any changed re-resolution (Section 9). |
| **D4** | "110-person team"? | A **metaphor**. Replaced by the real actor model in Section 12. |
| **D-fold** | Undo/redo semantics? | `UndoableEdit` **state deltas** with reference re-resolution, not blind command replay (Section 6.1). |
| **D8** | Threading model? *(2026-07-08)* | **Multi-threaded OCCT WASM from Phase 1**, single-threaded fallback (Section 8). Canonical re-sort (Section 4.5) is a hard requirement, since MT boolean ordering is non-deterministic. |
| **D9** | Verification: what's an oracle vs. a snapshot? *(2026-07-08)* | **Split** (Section 9): volume/area/length + topology counts are **independent oracles** (pythonocc); mass-checksum + adjacency-hash are **regression snapshots** (Bunyan-only), documented as such. |
| **D10** | OCCT operation-failure behavior? *(2026-07-08)* | **Reject + keep last-good**, marshal `Standard_Failure` safely as a typed failure (Section 6.4). Auto-repair + repro-bundle flagged for **v1.0.x**. |

| **D12** | Opening behavior on host resize? *(2026-07-08)* | **Per-opening anchoring parameter** — `fixed` (default) / `proportional` / `centered` (Section 5.1; `core_logic.md`). |
