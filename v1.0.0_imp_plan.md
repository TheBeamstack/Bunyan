# Bunyan v1.0.0 — Phased Implementation Plan

**Companion to:** `V1.0.0_spec.md` (and `core_logic.md`, `architecture.md`).
**Live status & handoff:** **`current_state.md`** — read it before starting work; it records what is already built and verified, and by whom.
**Revision:** **2026-07-14 — THE P4 REVIEW (`review_P4.md`) IS FOLDED IN, AND IT ADDS A PHASE.** Four owner rulings (2026-07-14) on the review's findings:
> **(1) A NEW PHASE — `P4.5 — THE INTERACTION MODEL` — LANDS BEFORE THE P5 FREEZE.** The review's headline: **there is no interaction model in any of the four contract documents.** The only one ever written down is *"button/drag → Command"*, which describes how an action **reaches** the model, not how a human **authors a building**. The words *snap · inference · alignment guide · preview · hover · gizmo · context menu · tool state* appear **nowhere in the repo.** ⇒ The app Amer built is a faithful implementation of what the plan says, and **what the plan says is a form over a command registry, not a CAD tool.** ⚠ **P5 freezes `BimObjectType` / `Command` / `SubShapeRef` — the exact contracts a tool layer pushes on** — so the shapes are reserved **before** the freeze, using the same *"reserve the shape, defer the body"* pattern that already served `sectionCut` / `importIfc` / `instantiate` / `exportBrep`.
> **(2) THE INTERACTIVE SCALE TARGET IS `10,000+` ELEMENTS.** This is a **binding budget, not an aspiration**, and it re-rates several items from *"cheap fix"* to *"architecture"* — see the new **P4 step 9 (the scale harness)** and the extrapolation in P4's status note. **The current architecture does not reach it, and we now know by how much.**
> **(3) DRAWINGS STAY v1.0.x — BUT THEIR CONTRACTS ARE RESERVED BEFORE THE FREEZE** (P5 step 6b). An annotation/dimension/tag is a **persistent reference to an element id and to `SubShapeRef`s**; reserving the shape now keeps 2D documentation **purely additive** later, which is what spec §438 already assumes and has never checked.
> **(5) ⚠⚠⚠ THE FULL CONSTRAINT MODEL IS IN v1.0.0 (D50) — AND IT IS THE LARGEST SCOPE RULING THIS PROJECT HAS MADE.** *Found by the review's second sweep:* **Bunyan has exactly ONE associative relationship — `opening → host face`. Everything else is absolute.** A **Level** cannot even be *moved* (no `core.updateContainer` exists — **floor-to-floor height is immutable after creation**); a **Grid**'s `gridRefs` are stored and validated and **never read by the build** (*Grid hosts nothing — D32's "Level organizes vertically, Grid horizontally" is half-built*); wall-to-wall joins do nothing. ⇒ **"Parametric" in Bunyan means *each element has a recipe*; in Revit it means *elements are constrained to each other*. Those are different products, and the second is what people mean by BIM.** **The owner ruled: v1.0.0 carries the constraint model.** ⇒ **New `P5 step 0` — the typed dependency graph and the associativity foundation — and it comes BEFORE the types, because it changes what a type's contract is** (a Wall gains base/top constraints; a column gains a grid host). ⚠⚠ **THE ANTI-FUSE RULE (§4h) STILL BINDS ABSOLUTELY: a wall-to-wall join is a DISPLAY/QUANTITIES cleanup, NEVER a fuse** — fusing re-owns 4 of the first wall's 6 faces and **retroactively breaks every window hosted on it** (measured, Entry 12). **A constraint is not a boolean.**
> **(6) A COMMAND MAY NEVER SILENTLY RE-IDENTIFY (D51).** *Reproduced:* `core.updateStyle` **accepts a layer rename** and **silently orphans every opening hosted on that layer** — the wall rebuilt at **full volume with no hole**, `brokenRefs` 0 → 1, no refusal, no warning. ⚠ **And D26 already states the rule for exactly this case, in the spec's own words:** *"reordering the segment array re-targets every reference into the shape, exactly as renaming a wall would… **and a document command must never do it silently.**"* **The rule existed; the guard did not.** ⚠⚠ **AND THE THING NO DOCUMENT SAYS: a style layer's NAME IS IDENTITY-BEARING** — it is inside the `SubShapeRef` token (`wall-X.finish.interior/face/y-min#0`) — **while the UI renders it as ordinary editable text.** ⇒ **`updateStyle` must REFUSE an orphaning rename/removal** unless the caller passes an explicit acknowledgement or a retarget map; and **the identity-bearing nature of layer names must be written into the contract.** *Free today; `Command`'s `argsSchema` freezes at P5.*
>
> **(4) THE FIXES LIVE IN THIS PLAN, NOT IN A SEPARATE CORRECTION DOC.** *Justification (owner-approved):* unlike P3 — whose six defects were revert-verifiable bugs in **shipped** code and earned a standalone `P3_correction_plan.md` — **most of these findings are UNBUILT WORK**, and unbuilt work belongs in the plan as **steps with exit criteria**, not in a second list beside it. A parallel fixes doc would be a **second description of one body of work**, which is precisely what domain rule 10 and D21 forbid (*generated, never maintained*) and what the review's own Hunt 3 hunts for. **`review_P4.md` remains the EVIDENCE** (every number, every reproduction) exactly as `review_P3.md` does; **this plan is the WORK.**

**Prior revision:** **2026-07-12b** — incorporates the **agent-native rulings D19–D23** (spec §4.6). *Nothing in the phase order changes*, but three things move: **P2 gains the geometric query ops** (they must land before the protocol freezes at P3); **P3's registry/undo work is now the agent surface** (`argsSchema` on `Command`, the generated capability endpoint, `UndoableEdit` returned as a diff + a reserved transaction id, `window.bunyan`); and **P4 changes its wiring rule — Amer builds the shell against the COMMAND layer, never against `KernelClient` directly** (D19). ⚠ *This was cheap only because the document model, the registries and the command layer had not been written yet. It is a greenfield decision on the one unbuilt layer, not a retrofit — and it stops being cheap the moment P4 lands.*
**Prior revision:** **2026-07-12** — incorporates the owner rulings from building the real kernel (`current_state.md` Entries 3–7): the kernel is **our own upstream-OCCT 7.9.3 WASM build** with our C++ op set (**D14**, `opencascade.js` rejected); **v1.0.0 ships single-threaded** (**D8 reversed** — no COOP/COEP, no `SharedArrayBuffer`, one artifact); **IFC import is IfcOpenShell → exact solids** (**D16**, `web-ifc` rejected); a **`measure` op** is in the protocol (**D17**); and **Bunyan is AGPL-3.0 open source** (**D15**). **Actors:** *Architect* (you) = interface contracts & scope; *Amer* (local PC, real browser) = browser hot path; *Zayd* (Hetzner CX23, headless) = kernel/WASM/Python/CI. See spec §12.

**Split contract-freeze rule (spec §12, decision D13):**
- The kernel worker's **flat versioned message protocol** (spec §3, incl. the tessellation **provenance channel**) freezes at the **end of P3** so Amer/Zayd parallelize.
- The **`SubShapeRef` / `BimObjectType` / `Command`** contracts stay **release-candidate** through the start of P5; they freeze only **after Wall + Opening exercise them** (P5 steps 3, 5). This prevents freezing type contracts that only a trivial type has stressed.
- The Architect owns any change to a frozen contract.

**Critical-path mitigation (spec §12):** P1→P2→P3 is Zayd-heavy and serial. Zayd publishes a **kernel mock** (protocol-conformant fake worker returning canned meshes + provenance) at the start of P2 so Amer can build the P4 shell in parallel instead of idling.

## Phase 1 — Foundations & Toolchain

**Objective:** A reproducible build that compiles OCCT to WASM (**single-threaded**, D8), boots a kernel worker behind the versioned protocol, deploys a static shell to Cloudflare Pages with the offline service worker wired, and runs CI with the golden/invariant harness. No geometry *features* yet — this phase exists so every later phase has a green pipeline to land on.

**Status (2026-07-12): steps 1–5 and 8 are DONE and green; the kernel is real and gated by CI. Steps 6–7 (Cloudflare deploy + service worker) remain, and are Amer's.** See `current_state.md` §1/§3.

**Driver:** Zayd (build/WASM/CI), Architect (protocol contract), Amer (shell scaffold + service worker).

**Steps**
1. Initialize the repo: `git init`, TypeScript + React app scaffold (Vite), pnpm workspace, ESLint/Prettier, `tsconfig` strict mode.
2. Stand up the Python tooling env (`pyproject.toml`/uv) with **`cadquery-ocp`** (OCP bindings to a native OCCT build) for **offline** golden seeding only — not CI — on a **pinned, documented environment** (spec §6.5), build/orchestration scripts, and pre-commit hooks.
   *(Corrected 2026-07-11: the original step named **`pythonocc-core`**, which **cannot be installed** here — its PyPI entry is an abandoned `0.16` placeholder and the real 7.9.x releases are **conda-only**, while the box toolchain is `uv` (no conda, no system pip). `cadquery-ocp` wraps the same OCCT 7.9. **System dependency:** `libgl1` — OCP pulls in VTK, which links `libGL.so.1`; without it `import OCP` fails on a headless box.)*
3. **Build the kernel: upstream OCCT 7.9.3 → WASM, statically linked with our own C++ op set** (decision D14). **✅ DONE** — recipe in `tools/kernel-build/`, artifact committed at `packages/kernel-occt/wasm/` (**3.98 MB / 1.47 MB gzip**), build id `occt-7.9.3-emcc-6.0.2` (spec §6).
   - **ONE artifact, single-threaded** (D8). No multi-threaded build, no `SharedArrayBuffer`, no capability detection — all deferred to v1.0.x.
   - **`opencascade.js` is REJECTED and must not be retried** (D14). It **cannot be linked on this box at all**: its `-flto` object cache forces a whole-program-optimisation link that is OOM-killed even for a *6-symbol* build. It is also 3 years stale, exposes all of OCCT to JS, and — decisively — **forecloses linking IfcOpenShell** (D16).
   - **The two choices that made it build on a 3.7 GiB box:** **LTO OFF**, and **modelling toolkits only** (`BUILD_MODULE_Visualization/ApplicationFramework/DataExchange/Draw=OFF`). Keep `TKHLR` (hidden-line removal → plans/sections), `TKOffset` (wall layers), `TKShHealing` (repairing imports), `TKBO`/`TKBool`, `TKFillet`, `TKMesh`.
   - ⚠ **The heaviest run in the project** (Docker + emscripten, ~2.5 h). It **must** follow the **box-discipline protocol** below — the dev box hosts the owner's live public sites.
   - 🔑 **But changing the kernel's C++ is only a ~60-second rebuild** — OCCT's static libs are already built and cached on the box; `link.sh` compiles one `.cpp` and links. **Only an OCCT *version bump* costs 2.5 h.** Iterate freely.
4. Define the **flat, versioned kernel message protocol** (TS types + `protocolVersion`), including the **tessellation provenance channel** shape (per-triangle→face and per-edge→edge `SubShapeRef` maps, spec §3) and the **typed-failure** result envelope (spec §6.4). Implement an empty worker that handshakes, echoes, reports kernel version, and demonstrates a marshalled failure.
5. Wire transferable `ArrayBuffer` message plumbing (main ↔ worker) with a typed request/response dispatcher, correlation ids, and **edit-coalescing/cancellation** hooks (spec §3).
6. Configure Cloudflare Pages static deploy; verify `application/wasm` MIME type and that the kernel boots in the deployed context. **No `_headers`, no COOP/COEP, no `SharedArrayBuffer` check, no CORP audit** — v1.0.0 is single-threaded (D8), so none of it applies. *(It all returns in v1.0.x when MT lands — spec §13.)*
7. **Service worker + PWA (decision D11):** precache app shell + the chosen WASM artifact keyed by **build id**; Web App Manifest for install; verify the app loads and runs a kernel round-trip **fully offline** after one online load.
8. Stand up CI: build, typecheck, lint, unit-test stub, the **golden/invariant harness** (spec §9) that runs the WASM build and checks a known box against (a) committed **reference-build oracle** values (volume/area/length + counts, seeded offline from native OCCT), (b) **closed-form** values where a formula exists, and (c) **self-snapshot** values (mass checksums, adjacency hash), plus `Bnd_Box` bounds. **The OCCT-native Python oracle never runs in CI.** Scaffold the **re-seed gate** and the **first-load size/time budget check** on a throttled profile (spec §8).
9. ~~Capability detection (multi- vs single-threaded WASM)~~ — **CANCELLED for v1.0.0** (D8). There is one artifact. The kernel still reports its identity (`name`/`kernelVersion`/`buildId`/`threading`) at handshake, which is what the app and the BREP-cache-staleness check actually need.

**Exit criteria**
- ✅ CI green: TS build + golden/invariant harness pass on the known box against the **real kernel** (reference-build oracle **and** regression snapshot), bounds pass. *(First-load budget: pending the app.)*
- ⬜ Deployed shell on Cloudflare Pages loads the kernel worker, reports its build id, and **works offline after first load**.
- ✅ Kernel message protocol v1 documented and versioned, including the provenance channel and the typed-failure envelope.

## Phase 2 — Kernel Core & Persistent Naming Subsystem (D1, critical path)

**Objective:** The hardest item in v1.0.0 (spec §4.5). Expose OCCT primitives/booleans/fillets through the worker, emit **provenance-tagged** meshes, and make sub-shape references **survive rebuilds** via `SubShapeRef` (functional/generative naming; no OCAF/TNaming). Everything parametric depends on this, so it comes before the document model.

**Status (2026-07-12): step 0 done; steps 1, 5, 6, 8 done FOR THE EASY CASE ONLY.** `makeBox` + `measure` + `tessellate` + `releaseShape` are real, provenance-tagged, canonically re-sorted and CI-gated. **⚠ But naming has only been exercised on a box** — where the operation can simply name its own faces and every edge is bounded by exactly two named faces. **That assumption dies the moment a boolean runs.** Steps 1 (cylinder/prism/boolean/fillet), **4 (history coverage — do this FIRST)**, 7 and 9 are the remaining work, and they are the real risk.

**Driver:** Zayd (kernel + resolver + regression harness), Architect (`SubShapeRef` interface, release-candidate).

**Steps**
0. **Publish the kernel mock** (protocol-conformant fake worker) so Amer can start P4 in parallel (spec §12).
1. Implement worker commands for base geometry: make box/cylinder/prism, extrude a profile, revolve, boolean union/subtract/intersect, fillet/chamfer on an edge. Each returns a `BuildResult` (`ShapeHandle` on success, **typed failure** on OCCT failure — spec §6.4), never throwing across the boundary.
   - **✅ STATUS (2026-07-13, Entry 14): COMPLETE. `makeBox`, `makeCylinder`, `extrude`, `revolve`, `boolean`, `fillet`, `chamfer`, `transform` are ALL BUILT** — the first time this step's own list has actually matched the code. `revolve` (D27) was the last, and it is **not** the prism with a rotation: a full 360° turn has **no caps** (and OCCT's cap accessors do not return null for it — they return a face that is not in the result), every lateral face carries a **seam**, and **a segment perpendicular to the axis reports no history at all while its face sits in the result**. All three were **measured** (`probe.cpp` cases 12-15) before a line of the resolver was written.
   - ⚠ **A LESSON WORTH MORE THAN THE OPS.** `extrude` and `chamfer` sat in this step's scope, unbuilt, through **two sessions that both declared P2 complete** — and nothing caught it, because every test built its walls out of boxes. They were found by **modelling a building with the protocol** and discovering the floor plate was unbuildable: a **Slab** is *"planar boundary + thickness"* (spec §5) and a real plate is not a rectangle. **Checking this list against the code would have found it in a minute; nobody did, for a month.** Read the exit criteria as a *specification*, not as a summary of what was done.
   - ⚠⚠ **AND THE SAME LESSON, ONE LEVEL DEEPER, FROM ENTRY 14: the op set being complete does NOT mean the naming is.** Building `revolve` gave us a round column; cutting a duct through one — an ordinary service penetration — **was refused by the resolver**, because a round column's single wrap-around lateral face makes the duct's two rims *genuinely symmetric* (spec §4.5). **It had nothing to do with `revolve` and had been reachable since Entry 9 on a plain `makeCylinder`.** Nobody hit it because **every boolean ever tested cut a box.** ⇒ **An op list is not a shape list. Cut the shapes.** **✅ RESOLVED in Entry 15 by the owner's D28 ruling — the bounded positional key** (step 6 below). *The lesson stands regardless of the fix: the gap was found by cutting a shape nobody had cut, not by reading the op list.*
2. Implement a BREP (de)serializer for `geometry-cache.brep` and shape handles that survive worker round-trips; treat inbound BREP as **untrusted** on load (spec §9). Implement the **`ShapeHandle` registry / lifecycle** (explicit free of intermediates; heap telemetry — spec §6.2).
   - **Status (audited 2026-07-13, Entry 13): the `ShapeHandle` registry + lifecycle + heap telemetry are DONE. ⚠ THE BREP (DE)SERIALIZER WAS NEVER BUILT — ZERO CODE EXISTS** (the string `geometry-cache.brep` appears only in comments). **No entry ever said so.** It is nonetheless named in **`.bnn`** (P3 step 4), the **cache-staleness** path (P3 step 5), and the **untrusted-BREP** security rule (§10).
   - ✅ **DECIDED 2026-07-13 — AND THE DECISION IS AN EXPLICIT DEFERRAL (D29), NOT A SILENCE.** The recipe is truth (`core_logic.md` §2), so the BREP cache is a **pure optimisation**: a document can always rebuild from `scene.json`. What it buys is **load time on a real building** — **a number that does not exist yet**, because there is no document model to measure it with. ⇒ **The owner ruled: decide at P3 step 4, WITH the measurement.** Until then **nothing may assume the file exists**, and every doc that claimed it now says so (spec §6, `architecture.md`, the security rule). ⚠ **If it is dropped, `.bnn` must stop claiming the file and P3's exit criteria change** — that edit is part of the P3-step-4 decision, not an afterthought.
3. Define the opaque **`SubShapeRef`** interface (Architect, **release-candidate**) — structured path (`nodeId` + `role` + `occurrence`), never a raw OCCT index.
4. **⚠ VERIFY OCCT HISTORY COVERAGE FIRST — THIS IS THE NEXT TASK, AND IT IS EMPIRICAL (spec §4.5 caveat).** Before designing the general resolver, **find out what OCCT actually gives us**: confirm `Generated`/`Modified`/`IsDeleted` **edge/vertex** coverage for each needed operation — especially **a fillet on an edge produced by a boolean**, the hardest case. Add the C++ ops (`makeCylinder`, `boolean`, `fillet`) and *measure the history*, rather than designing against what the docs imply. Record which reference classes are safe; wrap or defer any with inadequate history (**never** fall back to geometric guessing). *(`TKBO`, `TKBool`, `TKFillet`, `TKOffset`, `TKShHealing` and `BRepTools_History` are all already in the build; the C++ rebuild is ~60 s.)*
5. Implement the **functional-naming propagation layer** in the worker (TypeScript): for each operation, read the maker maps and assign each output sub-shape an identity derived from the operation + its input identities. Graph is hybrid: coarse (feature) for history, fine (primitive-op) for propagation.
6. ✅ **DONE.** Implement the **structural tie-break** for 1→N splits/merges, with a **bounded positional key** (mm-rounded centroid, fixed rounding, spec §6.5) as the sole last resort for genuinely symmetric splits. **⚠ THE KEY WAS DELIBERATELY WITHHELD UNTIL A REAL MODEL NEEDED IT, AND THEN RULED IN BY THE OWNER (D28, 2026-07-13, Entry 15):** edges got their structural tie-break in Entry 9, faces in Entry 11 (a groove across a wall), and the **key itself** only when a duct through a **round column** produced two rims that no structural rule could separate. It is the **third** sort term — consulted only after derivation *and* structural signature have both tied — it **orders, never identifies**, and a collision on the mm grid is **refused**, not tolerated (§6.5). **It is the only place geometry touches the identity path.** Run every operation's `Generated`/`Modified` output through a **canonical re-sort** before assigning IDs, so **the kernel's traversal order can never leak into a name**. *(Note: v1.0.0 is single-threaded (D8), so the original multi-threading justification does not apply today — but **the re-sort still stands**, and it is the precondition for enabling MT in v1.0.x without invalidating saved files. Implemented for the box.)*
7. Implement the **rebuild engine**: persist the identity **token map**; on edit, rebuild only the affected subgraph and re-propagate identities; on load, deterministically replay to re-bind tokens. Mark a reference **broken** for **manual retargeting** (never silently reattach) when its target no longer exists.
   - **⚠ Status (audited 2026-07-13, Entry 13): NOT BUILT — and the BROKEN-REFERENCE STATE DOES NOT EXIST ANYWHERE.** `core_logic.md` **domain rule 3** and **§7** mandate `resolved ↔ **broken**`, with a broken reference being *"a first-class, visible state awaiting **manual retargeting**, never auto-healed."* **Today an unresolvable ref throws `UNRESOLVED_SUBSHAPE_REF` and the whole operation fails.**
   - ⇒ The promise *"predictable breakage beats silent wrongness"* is **half-kept**: the breakage is **loud** (good), but **a document cannot survive carrying one broken dependent**, and there is **no retarget path**. **Deleting a wall that a window is hosted on has no defined behaviour.**
   - ⚠ **This step is misfiled here. It is DOCUMENT-MODEL work and belongs in P3** — it needs the scene graph and the dependency DAG, neither of which exists in P2. **P5's Opening depends on it.** Do it in P3.
8. **Tessellation command with provenance**: convert a `ShapeHandle` to a mesh buffer (positions/normals/indices) **plus** the per-triangle→face and per-edge→edge `SubShapeRef` maps (spec §3) as transferables — display artifact + picking substrate.
9. Build the **persistent-naming regression suite**: "edit host parameters → assert dependent references re-resolve to the correct sub-shape, or correctly break." Include a large-extent model (spec §6.5). This is also the **reference-stability corpus** for the kernel-migration gate.
10. **✅ DONE (Entry 9) — THE GEOMETRIC QUERY OPS ARE IN, BEFORE THE FREEZE** *(decision D23/D25, spec §4.6.5)*. **`bounds`** (whole shape **or one NAMED sub-shape** — *"where exactly is the south face of that wall?"*, a question only persistent naming makes askable), **`distance`** (minimum separation + the two witness points — **zero doubles as the clash primitive**), **`classifyPoint`** (`inside`/`outside`/**`on`**). ⚠ **They read the B-Rep, never the mesh, and return millimetres and identities — never triangles**; a tessellated column is smaller than the real one by its chord error, so an agent reasoning about clearances from the mesh would under-report every clash in the project. **Implemented in BOTH kernels** — the mock answers them in closed form for a box, so the agent/query path is buildable with no wasm. **Document-level queries still need NO kernel op at all**: `getSceneGraph`/`getElementById`/filter-by-type read the **parametric recipe**, which is the truth (P3). **⚠ Placement (`at`) was added to the primitives in the same pass** — without it a boolean can only bite a *corner* off a wall, so a window in the middle was unreachable. **`transform` (rotation/mirror) is NOT in, and is the next op that will want in before the freeze.**

**Exit criteria**
- Boolean, extrude, revolve, fillet/chamfer match committed **reference-build-oracle values + regression snapshots + bounds** (spec §9).

>

>   button / drag ─┐
>   agent verb ────┼──►  Command registry ──► DocumentContext ──► KernelClient ──► OCCT

> ```

If no Command expresses it, the UI does not do it.**

## Phase 4.5 — THE INTERACTION MODEL ⚠⚠ NEW (owner ruling, 2026-07-14 — `review_P4.md`)

**Objective:** Write down, and then build, **how a human authors a building** — and do it **before the type contracts freeze**, because a `Command` whose `argsSchema` has never been driven by a pointing device is a `Command` frozen against a guess.

> ### ⚠⚠ WHY THIS PHASE EXISTS (read it; it is the calibration)
>
> The owner looked at the P4 shell and said it was **primitive next to ArchiCAD and Revit.** He was right, and **the cause is not in Amer's React.** Search `core_logic.md`, `architecture.md`, `V1.0.0_spec.md` and this plan, and the **only** interaction model ever written down is:
>
> ```
>   human (button / drag) ─┐
>   agent verb ────────────┼──►  Command registry ──► DocumentContext ──► kernel
>   MCP [v1.0.x] ──────────┘
> ```
>
> **That is a diagram of how an action REACHES the model. It is not a model of how a human AUTHORS a building** — and the project has been treating the first as though it were the second. The words **`snap`** *(every hit in the repo is "snapshot")*, **`inference`**, **`alignment guide`**, **`rubber band`**, **`preview`**, **`hover`**, **`gizmo`**, **`context menu`**, **`tool state`** appear **nowhere in any document.** There are **sixteen domain rules and every one is about the model**; there are **five north-stars and the one about authoring is the *agent's*.**
>
> **⇒ So this is what it takes to place a window in Bunyan today.** The ribbon is generated from the command registry, so `core.createElement`'s `argsSchema` is rendered as a **form**, and the human must type:
>
> | field | the control the schema produces | what the human must type |
> |---|---|---|
> | `typeId` | text input | `core.opening.v1` |
> | `params` | **JSON textarea** | `{"width":1200,"height":1400,"offsetU":1500,"offsetV":900}` |
> | `hostId` | text input | the host wall's **ULID** — `wall-01J8Z3K7Q2…` |
> | `hostRef` | **text input** | `wall-01J8Z3K7Q2….finish.interior/face/y-min#0` |
> | `placement` | **JSON textarea** | `[{"kind":"translate","by":[6000,0,3200]}]` |
>
> **A human must hand-type a persistent-naming derivation token to place a window** — and **D44** says an element id must *never* be shown to a user as a name, yet one must be typed here from memory.
>
> **⇒ THE DIAGNOSIS, AND IT IS ONE SENTENCE: `argsSchema` IS A MACHINE-READABLE CONTRACT FOR AN AGENT, AND THE APP IS USING IT AS A UI SPECIFICATION FOR A HUMAN.** Those are not the same artifact. **D21 ("one schema, three consumers") is exactly right for the property panel and exactly right for the agent tool list; for the RIBBON it silently substituted a *form* for a *tool*.** In Revit and ArchiCAD a ribbon button does **not** open a form — **it activates a TOOL**, and the tool collects its own arguments *from the viewport*: click a point, click another, snap to a grid line or a wall end, watch a rubber-band preview, type `5000` to override, press `Esc` to cancel. Only at the end does **one** Command commit.
>
> **⚠ THE TOOL LAYER DOES NOT WEAKEN D19 — IT IS THE THING THAT MAKES D19 SURVIVABLE.** It ends in exactly one Command dispatch, so the human and the agent still share one door. **What it changes is not the door; it is what the door's ARGUMENTS have to look like** — and those freeze at P5.

**Driver:** Amer (the tool layer, the browser) + **Architect** (type semantics, the parameterisation call, the reservations) + Zayd (the spatial/geometric seam, and any kernel op the snapping needs).

**Steps**

1. **⚠ WRITE THE INTERACTION MODEL DOWN — IT IS A CONTRACT DOCUMENT, NOT A UI SKETCH.** It lands in `architecture.md` (*how it is built*) and adds **one domain rule** to `core_logic.md` §8, because the invariant is a domain invariant:
   > **Domain rule 17 (proposed): A TOOL COLLECTS INPUT; ONLY A COMMAND CHANGES THE MODEL.** A tool is a **UI state machine** that gathers arguments — a point, a face, a length — and **commits exactly one Command.** It is **never** a second command layer, it **never** touches the kernel, and **an in-progress tool interaction is not model state** — nothing half-drawn is ever in the document, so a refresh, an undo or an agent query can never observe it. *(This keeps domain rule 9 intact: there is still exactly one command layer, and a tool is upstream of it.)*
2. **THE TOOL STATE MACHINE.** `activate → collect(n inputs) → preview → commit ONE Command` · `Esc` cancels at any step and leaves **no trace** · `Enter`/typed numbers override the pointed value (**numeric dimension entry** — the thing that makes a CAD tool precise rather than approximate) · a tool is a **registry entry**, like everything else in this product, so **a new type ships its tool the way it ships its schema** (D21's spirit, applied to input rather than to forms).
3. **⚠⚠ THE SPATIAL QUERY SEAM — THE MISSING SEAM, AND IT IS THE REAL WORK OF THIS PHASE.** **No actor in the app can currently ask a geometric question in world space, and every snap is one.** The three existing seams each refuse it by design:
   - the **agent surface** — *"queries return SEMANTICS, never triangles"*, and its `Query` filters are `typeId · styleId · containerId · materialId · loadBearing · discipline`: **not one spatial predicate**;
   - the **render seam** — `tessellate` and nothing else;
   - the **`GeometryGateway`** — the document's, not the UI's.
   ⚠ **The kernel already has the ops** (`distance`, `bounds`, `classifyPoint` are live and tested). **What is missing is a seam that lets the UI reach them.** Design it as a **read-only spatial/snap seam** (it authors nothing, mints no identity, and therefore does not violate D19 — the same argument that legitimised `RenderGateway`). ⚠ **DESIGN DECISION TO RECORD:** snapping against a **browser-side index built from the retained mesh + `edgePositions`** (cheap, per-frame, approximate) with the **kernel's exact ops as the confirming fallback** — versus every snap round-tripping to the kernel (exact, and **far too slow at 60 fps**). *Recommend the former, and say so in writing, because "the snap that lied" is a class of bug that is very hard to see.*
4. **⚠⚠ THE PARAMETERISATION CALL — AND THIS IS THE ONE THAT TOUCHES THE FREEZE.** **Every MVP type must be parameterised by the gesture that authors it.** Today a Wall is `{length, height}` plus a `placement` array of rigid motions. In every real BIM tool a wall is authored and edited **by its baseline** — two points — and its length is **derived**. This is not cosmetic:
   - **"drag the wall's free end" is the single most common gesture in BIM**, and under the current shape it is a **compound** change to `length` **and** `placement` at once — **which no Command expresses.** Domain rule 9 then bites: *if no Command expresses it, the UI does not do it.* ⇒ **The frozen contract would make the most ordinary gesture in the product either impossible or a private path that breaks D19.**
   - **A baseline is also what makes wall-to-wall corner joins, grid-hosting and "walls that follow a level" expressible at all** — the first of which spec §438 already defers to v1.0.x **as a display/quantities concern**, which is only true *if a baseline exists to join*.
   - ⇒ **Architect's call, recorded in the spec's decision list, before P5.**
5. **⚠ RESERVE THE COMMAND SHAPES — THE PATTERN THIS PROJECT HAS ALREADY USED FOUR TIMES AND IT HAS NEVER ONCE BEEN WRONG.** *(`sectionCut`, `importIfc`, `instantiate`, `exportBrep`/`importBrep`: **the expensive thing to get wrong is the payload shape, not the body.**)*
   - **⚠⚠ THERE IS NO COMMAND THAT MOVES AN ELEMENT.** The twelve core commands are all CRUD; **`placement` is set at creation and can never be changed.** P5 step 7 lists `move / rotate / copy / array` — **their arg shapes must be reserved HERE, having been driven by a pointing device**, not designed in the same phase that freezes them.
   - Reserve, at minimum: **`core.setPlacement`** (or `core.move`/`core.rotate`), and whatever the baseline call (step 4) implies for **`core.setParams`** on a drawn element.
6. **THE PREVIEW, AND THE TRAP INSIDE IT.** D42's **universal `dryRun`** is the *semantically* perfect preview — the real command, the real kernel, the result discarded. **It is also ~100 ms per frame** (measured: a one-wall rebuild), so **it cannot drive a 60 fps rubber band.** ⇒ **The preview is a cheap local approximation drawn by the renderer, and it is NEVER truth**; `dryRun` is what backs a *commit-time* confirmation ("this will also delete 3 windows"). ⚠ **Write that distinction down, or somebody will make the preview authoritative and re-introduce the half-committed state that D42 exists to abolish.**
7. **SELECTION, VISIBILITY AND FILTERING — MISSING ENTIRELY, AND AT 10,000 ELEMENTS IT IS NOT OPTIONAL.** There is no hide, no isolate, no selection set, no view filter anywhere in the document or the app. ⚠ **It is a UI concern (additive, no contract cost) — but it must ride on the same `nodeId`/element identity the renderer now carries** (P4 step 2a), and it should filter on what the model already knows: **`discipline` per part** (D45), `loadBearing`, `containerId`.
8. **KEYBOARD.** `Esc` · `Enter` · numeric entry · undo/redo. ⚠ **There is currently not one `keydown` handler in the entire app.**

**Exit criteria**

   - **`Space`** — `IfcSpace`. ⚠ **It was missing, and the spec modelled "a room" as a COMPOSITE VERB** (4 walls + a slab + a door) — **a macro, not a thing.** It carries a name, a number, and an **area/volume from the real geometry**; **floor area is architecture's most-scheduled quantity** (paint, ceilings, screed). ⚠⚠ **BUT ITS EXTENT MODEL IS UNDEFINED AND FREEZES HERE (Freeze Gate row ⓖ): "area from the real geometry" — WHICH geometry?** A `Space` today is `{id, kind, name, number}` with **no boundary.** Decide before it freezes: does a Space own a **boundary profile** (authored like a Slab's), is its extent **derived from the bounding walls** (a room-bounding solve — heavier), or is the field **reserved**? *A Space whose area is unanswerable forecloses the most-scheduled quantity in the building — domain rule 8.*

## Phase 6 — 2D Views & IFC Import

**Objective:** Prove the kernel is the single source of truth by generating 2D views as *real cuts* of the real geometry, and achieve IFC4 **import** through the codec registry. (IFC **export** is deferred — decision D3.)

> ⚠ **v1.0.0 2D SCOPE IS "MINIMAL" (D58, owner ruling 2026-07-21): one plan + one section/elevation + ONE schedule (quantity view).** The section cuts prove the kernel-is-truth invariant (rule 17); the one schedule proves the quantity→documentation path end to end. **The FULL documentation apparatus — detail views, tags, dimensions annotation-scaled, view-graphic overrides, sheets, titleblocks, viewports, revision clouds — is post-v1.0.0** (the largest single parity item; see "Road to Revit parity" below). ⚠⚠ **But the ANCHORING CONTRACTS for all of it freeze at P5 (row Ⓐ, D58)** — a View descriptor, a Dimension/Tag on `SubShapeRef`+vertex, a Schedule bound to type/param/quantity, a Sheet/Viewport shell — so the v1.0.x build is additive, never a frozen-contract amendment.

**Driver:** Zayd (section-cut kernel op + IFC importer + import corpus), Amer (2D view rendering + import UI), Architect (IFC mapping validation).

> ### ⚠⚠ THIS PHASE NEEDS TWO SETS OF KERNEL OPS THAT THE P3 FREEZE DOES NOT ACCOUNT FOR *(Entry 13)*
>
> **Step 1 needs a `sectionCut` op. Step 3 needs IFC-import ops.** **The protocol froze at the end of P3**, and **neither was in it.** So this phase, as scheduled, **begins by amending a frozen contract.**
>
> **This is not a P6 problem to discover in P6 — it is a P3 problem, and P3 step 8b is where it must be settled** (reserve the op shapes before the freeze, or re-word D13 so that *adding* an op is explicitly additive and permitted). **If you are reading this in P6 and it was never settled, stop and raise it with the Architect before writing an op.**

**Steps**
1. Implement the **section-cut** kernel operation: cut the actual B-Rep at a plane, extract profile curves (not a separate drafting engine — spec §5.2).
2. Register a **plan view and one elevation** in the View/Representation registry (spec §4.4) rendering the cut profiles; link them live to the 3D document graph. (The elevation exercises a non-horizontal cut plane.)
3. Implement the **IFC importer** — **IfcOpenShell, producing exact B-Rep solids** (decision D16) — against the Codec registry: **import = mapped-or-GenericSolid** — recognized IFC types (`IfcWall`/`IfcSlab`/`IfcColumn`/`IfcOpeningElement`) map to native parametric types; everything else imports as GenericSolid with **exact solid geometry preserved** (non-parametric).
   ⚠ **`web-ifc` is rejected — it returns triangles**, which cannot be measured, sectioned, booleaned or edited; an imported model would be a *backdrop*, not a building (spec D16, `core_logic.md` §3.5).
   ⚠ **This is a C++ build task, not an npm install.** IfcOpenShell must be **compiled and linked against *our* OCCT build** and exposed as new ops in `kernel.cpp` — which is possible only because we own the kernel (D14). Budget for a kernel rebuild, and note the OCCT static libs are already cached (~60 s for the link; the IfcOpenShell compile itself is new).

   > ### ⚠⚠ THE IMPORTER REGISTERS **A TYPE PER IFC CLASS** — IT DOES NOT DUMP EVERYTHING INTO ONE `GenericSolid` *(reserved by **D45**, owner ruling 2026-07-13)*
   >
   > **Every Part carries a `discipline` (D45), and a Type with no Style stamps it from its `defaultDiscipline`.** ⇒ If a consultant's IFC file — **ducts (MEP), cladding (architectural) and braces (structural)** — lands as one undifferentiated `GenericSolid`, **every imported part gets ONE discipline**, and **D45's per-part work-package routing is dead on the entire import path.** Planitor cannot route it and Miqdar cannot filter it.
   >
   > ⇒ The importer **maps each IFC class to a registered Type** (`IfcDuctSegment` → a type whose `defaultDiscipline` is MEP; `IfcCovering` → architectural; `IfcMember` → structural), and **only a genuinely unmappable entity** falls through to a bare `GenericSolid`. ⚠ **This is not inference and it is not a guess: the IFC class is authored data from the source model** — and *"Miqdar must never guess"* (D36) applies to us reading someone else's file exactly as it applies to them reading ours. **A new Type is an additive registration (domain rule 5), so the cost of each is a registration, not a core edit.**
   >
   > ⚠ **And an unmappable `GenericSolid` carries NO discipline rather than a wrong one** — it appears in no discipline filter and no work package until a human classifies it (`core_logic.md` §3.5: *geometry preserved, non-parametric*). **A refusal is visible; a plausible wrong answer is not.**
3a. **⚠⚠ THE CLEAN DELTA PACKAGE EXPORTER — THE ECOSYSTEM'S CHANGE FEED (D34). This is what connects Bunyan to Planitor, and it did not exist.**
   Register it as a **File Format Codec** (spec §4.3, §7a). It is **an already-existing contract** shared by Planitor and BIMsync (`Planitor/v2.2_spec.md` §4) — **do not invent a transport; emit the one that exists**, as `source: "bunyan"`, and validate against the **shared JSON Schema in CI** (D36).
   - `pei` = the element's **`id`** — stable **by construction**. **Do not mint one. Do not fingerprint.** *(BIMsync must do both, for foreign models whose identity was lost. Ours never was.)*
   - `change_type` is **READ OFF THE `UndoableEdit` LOG**, computed against the last **issued Model Revision** (P3 step 4) — **never inferred by diffing two models.** ⚠ **`reidentified` cannot occur**; `split`/`merge` are reported **authoritatively** (they were *commands*).
   - `quantity.basis: "exact"` — from `measure` on a `ref`, **per Part, per Material** (D30/D33). ⚠ **This is the payoff:** Planitor otherwise reconstructs a steel column's weight through a fallback ladder that **hardcodes density 7850** because IFC will not tell it. **We have the Section, the Material's density, the axis length and the true volume. The ladder collapses into a lookup — do not throw that away by emitting a rolled-up element quantity.**
   - `spatial_container_code` from the **spatial tree** (P5 step 1, D35) — which **is** Planitor's LBS.
4. Make the IFC-schema binding an **abstraction** (`IfcSchemaVersion`) so the future **exporter** and IFC5/IFCX are later sibling registrations, not rewrites (decision D3). ⚠ **IFC is the door for the OUTSIDE WORLD — it is not the ecosystem's internal transport, and it cannot be:** it carries neither the parametric recipe, nor a `SubShapeRef`, nor a stable id (D34).
5. Build the **IFC import-fidelity corpus**: seed from public IFC test models + Bunyan-authored `.bnn` samples; run import fidelity in CI. ⚠ **Fidelity means *solids*, not pictures**: assert **volume/area** (via the `measure` op) and type mapping within tolerance — not merely that something rendered. *(Full export round-trip is a v1.0.x gate.)*
6. Validate IFC import mappings with the Architect (AEC correctness) for each MVP type.
7. **Harden import**: decompression size/ratio caps + entry-count limits on `.bnn` zips, IFC schema validation, parsing inside the worker with a timeout — malformed/hostile files fail safe without hanging or OOM-ing the tab (spec §9).

**Exit criteria**
- A plan view and a (non-horizontal) elevation are generated as genuine section cuts of the live model and update when the model changes.
- A representative IFC4 model imports with geometry + type fidelity within tolerance (mapped-or-GenericSolid), and the import corpus passes in CI.
- Malformed/hostile `.bnn`/IFC inputs fail safe (no hang/OOM/crash).

**Steps**
1. Cross-browser matrix: Chromium (full File System Access API) and the universal fallback path (Firefox/Safari: download/upload save). **No threading matrix — v1.0.0 is single-threaded everywhere** (D8), which is one fewer axis to test and one fewer way to fail.
2. Performance at scale: GPU-side culling/instancing (compute shaders / TSL) for thousands of repeated elements; measure and set large-model budgets (tessellation time, memory/heap ceiling, save latency) and confirm the **first-load size/time budget** (spec §8) is met in CI.
   > **⚠⚠ THE TARGET IS NOW A NUMBER, AND IT IS BINDING: `10,000+` ELEMENTS, INTERACTIVELY (owner ruling, 2026-07-14).** And **the measurements that price this step are taken in P4 step 9, not here** — because two of the four axes **cannot be fixed additively in P7**:
   > - **Renderer batching/instancing/LOD** must land **before** picking (P4 step 4) and section views (P6) are built on top of the renderer. **After that it is a rewrite, not an optimisation.** *(Today: one `THREE.Mesh` per part ⇒ **~16,000 draw calls at target**, ~10–20× a 60 fps budget.)*
   > - **⚠ WASM-HEAP EVICTION IS A DOCUMENT-LAYER DESIGN, NOT A RENDERER ONE** — *what may be released and rebuilt on demand* is a question about the recipe, the handles and the rebuild engine. **It therefore touches contracts, and it must be known BEFORE P5 FREEZES.** Today **every solid the document builds stays live in the WASM heap for the entire session and nothing evicts**; a 10,000-element model is ~16,000 live OCCT solids, and **WASM32 caps at 4 GB with a browser tab dying well before it.** **This number does not exist yet. It is the most dangerous unknown in the project.**
   > - ⇒ **If P4 step 9's numbers say the target is unreachable single-threaded, that is an Architect decision about D8 (multithreading is v1.0.x), and it must be raised THEN — not discovered here.**
3. Incremental rebuild optimization: only rebuild/re-tessellate the affected subgraph on edits, using P3 dependency tracking; validate edit-coalescing/cancellation under rapid drag. ⚠ **The re-tessellation half of this is pulled forward to P4 step 2b** — it is not a P7 optimisation, it is **90% of the cost of every edit today** (measured), and it must be right before the renderer grows.
4. **Offline/PWA hardening (decision D11):** verify service-worker cache invalidation on a **kernel-build-id** bump, offline cold-start, and the update flow. **One WASM artifact to cache** (D8).
5. **Visual regression** against **both** WebGPU and WebGL2 backends (`renderer.info`/`stats-gl`) — O5.
6. Resilience pass: corrupt-cache recovery, broken-reference retargeting UX (spec §4.5), operation-failure UX polish (spec §6.4), capped-ring autosave limits, migration edge cases, WASM heap ceiling behavior.
7. Accessibility, keyboard shortcuts, empty/error states, minimal in-app onboarding for the end-to-end flow.
7a. **Agent-surface hardening (D19–D23).** Confirm the **end-to-end modelling task passes driven entirely by an agent** through `window.bunyan` (the P5 criterion, re-run at release scale); confirm `listCommands()`/`listTypes()` are **generated** and complete (no registered command is missing a verb, no verb lacks a schema); confirm typed failures are legible to a caller with no source access. **Document the agent surface in the README** — it is a headline capability of an open-source Revit challenger, not a footnote. ⚠ **Confirm the trust boundary** (spec §4.6.6): `window.bunyan` is page-global, which is acceptable **only** while the page runs no code we did not author — **so the Pyodide macro console must not ship in v1.0.0** (it is already deferred, §5.3; this is a second, independent reason).
8. Release engineering: version tagging, `manifest.json` schema/version finalization, **kernel-upgrade policy — OCCT upgrades within 1.0.x allowed only behind the migration gate replaying the reference-stability corpus** (spec §9), production Cloudflare Pages pipeline (preview → production), asset preload/streaming.
   **Licensing (decision D15 — spec §11):** ship `LICENSE` (**AGPL-3.0**), the **CLA**, AGPL file headers, and the **OCCT + IfcOpenShell attribution notice** (LGPL *requires* prominent notice — README **and** the app's About screen), plus a `NOTICE`/third-party section. ⚠ **The CLA must exist before the first external PR**, not before release — a patch merged without one can never be relicensed commercially.
9. Final regression run (split golden/invariant + persistent-naming + IFC-import + operation-failure + command unit + visual + first-load budget) all green → tag **v1.0.0** and deploy.

**Exit criteria**
- Full end-to-end task passes on Chromium and on at least one non-Chromium browser via the fallback path; app works **offline after first load** with correct update-on-new-build behavior.
- **Large-model performance + first-load budgets met — AND "LARGE" NOW MEANS `10,000+` ELEMENTS, INTERACTIVELY** (owner ruling, 2026-07-14). The four axes, each with a committed budget set in P4 step 9: **edit latency · cold load · draw calls / frame time · WASM heap ceiling.** *(No threading fallback to verify — v1.0.0 is single-threaded, D8. ⚠ **Unless P4 step 9 says the target is unreachable that way** — in which case D8 is an Architect decision re-opened **on the measurement**, which is how every performance call in this project has been made.)*
- All test suites green in CI (split geometry harness, persistent-naming, IFC-import fidelity, operation-failure, command unit, visual regression on both backends).

## Cross-cutting practices (all phases)

- **Contract-first, split-freeze:** never edit a frozen contract without Architect sign-off. The message protocol freezes at P3; type contracts freeze after Wall+Opening in P5 (decision D13). New features are additive registry entries (spec §4). The **`agentApi` surface is versioned separately** and does not inherit the P5 freeze (D22).
- **⚠ ONE COMMAND LAYER — the rule with no exceptions (D19, spec §4.6).** Every action, from every actor, is a Command. **`DocumentContext` is the only holder of a `KernelClient`** — enforce it with a machine check, not a convention. A capability reachable only through the UI is a capability an **agent can never have**, and nobody finds the gap until an agent is asked to use it. **A new command is an agent verb automatically** (its `argsSchema` generates the tool definition — D21); there is **no separate agent feature list to keep in sync**, by construction. ⚠ **An agent must never be handed a kernel op** (`makeBox`, `tessellate`): that would create a solid **no entity owns, no undo can remove and no `SubShapeRef` names.**
- **Snapshot-gated geometry:** no new `buildGeometry` merges without passing the **reference-build-oracle** checks (volume/area/length + counts, via the exact **`measure` op** — D17, never off the mesh) **and** the **regression snapshots** (mass checksum, adjacency hash) **and** committed **re-seeded goldens** on the pinned env (spec §9). The re-seed rule fails geometry changes that lack them. Verification is scoped by spec §9.0: **we trust OCCT; we verify our own code** — and every bug the harness has caught so far has been *our misreading of an OCCT API*, never an OCCT defect.
- **⚠ Naming is verified AS NAMING.** A mislabelled sub-shape passes every numeric check — the geometry is exact and only the *names* are wrong (it has already happened: four of a box's six faces). Any new op must assert **what its names actually refer to**, not just that its volume is right.
- **Kernel-migration gate:** a change to the **kernel build id** (`occt-<version>-emcc-<version>`) within 1.0.x must replay the reference-stability corpus and fails if any `SubShapeRef` re-resolves differently. **Re-seed the goldens whenever OCCT itself moves** — the oracle (`cadquery-ocp`) and the WASM build must stay on the *same* OCCT version, or the harness is comparing two different kernels.
- **Failure-safe kernel:** every worker op returns a typed `BuildResult`/`CommandResult`; OCCT failures never crash the tab, never produce a partial edit (spec §6.4).
- **Memory discipline:** explicit `ShapeHandle` lifecycle; no rebuild leaves leaked WASM heap (spec §6.2).
- **Offline-first:** every release ships a working service-worker cache keyed by build id (spec §8).
- **CI stays green + first-load budget:** every phase lands on a green pipeline; a broken golden/invariant, naming, import-fidelity, or first-load-budget check blocks merge.
- **Actor placement:** display-dependent work runs where a real browser exists (Amer/local); kernel/WASM/Python/CI runs headless (Zayd/Hetzner); Amer works against Zayd's kernel mock until P2 lands.
- **Risk watch — two risks now, not one, and both are Zayd-concentrated kernel work:**
  1. **P2, Persistent Naming (D1) — still the #1 schedule risk.** ⚠ **And do not be reassured by the green box.** Naming currently works on the *easy* case: `makeBox` names its own faces, and every edge is bounded by exactly two named faces. **A boolean breaks that assumption**, and today the kernel deliberately *refuses* to name what it cannot derive structurally — which is the right failure mode and also a wall you hit on the first cut. The real work (history coverage for booleans/fillets) has **not started**. If the general resolver stalls, apply the spec §4.5 fallback contract — but do **not** ship v1.0.0 until `SubShapeRef` is real, since retrofitting it would break `scene.json`.
  2. **P6, IFC import (D16) — a NEW risk, created by a good decision.** Choosing exact solids over triangles means IfcOpenShell must be **compiled and linked against our OCCT**: a second C++ build, not a library integration. This was the right call (triangles break the core invariant, `core_logic.md` §3.5) and it is only *possible* because we own the kernel (D14) — but it moved a chunk of C++ build work into a phase that used to be mostly wiring. **Estimate it as kernel work.** *(Mitigation available and cheap: spike the IfcOpenShell link early — even during P2 — to find out whether it builds at all against our toolchain. Discovering it does not, in P6, would be very expensive.)*

### Box-discipline protocol for heavy runs *(owner ruling, 2026-07-11 — binding)*

**Context a new agent must not have to discover the hard way:** Zayd's dev box is small (**~3.7 GiB RAM + 2 GiB swap**) **and it is simultaneously the production host for two live public sites.** The OCCT→WASM build (Docker + emscripten), large IFC parses, and big benchmarks are all capable of exhausting it. An out-of-memory event here does not just fail a build — it can **take the owner's public websites offline.**

**The rule: never run anything that would overload the box.** Before any heavy run:

1. **Check headroom** (`free -h`) and **constrain the run itself** — cap Docker memory, cap compiler parallelism (`-j`). A build that cannot balloon cannot take the box down.
2. **Free memory by pausing other projects' NON-production services.** The owner has **pre-authorized** pausing work belonging to projects he is not actively using: **Planitor** (`planitor-pg`), **Chantier_Manager** (`chantier_test_pg`, `chantier_test_redis`), **Portique_Designer** (no containers), **SmartBar**. Graceful `docker stop` only — **never** `kill`, **never** `rm`, **never** remove a volume. Check that project's `current_state.md`/handoff for active work first.
3. **NEVER touch production. These are not pause targets under any circumstance, including box strain:**

   | Container | What it is | Why it is untouchable |
   |---|---|---|
   | `portfolio-caddy-1` | Caddy on **:80/:443** | Serves the **live** `beam-stack.com` and `daoudi.beam-stack.com`. Stopping it takes both public sites offline. |
   | `beamstack-contact` | Lead-capture service | Handles **real inbound leads** and sends visitor-facing email. Stopping it drops real business enquiries. |

   These are light apps that use the dev box **as their production box**. They are cheap to leave running and expensive to interrupt — the opposite of the trade-off that justifies pausing anything else.
4. **Restore what you paused** the moment the heavy run ends, and verify it is healthy. ⚠ `chantier_test_pg` / `chantier_test_redis` are `restart=no` — they will **not** come back on their own.
5. **Record the pause + restore** in the box-local `last_session_work.md`.

**If a run cannot be made safe by the above, do not run it — escalate to the owner** with the memory numbers and the options. (Full box rules: the box-local `cross_projects_policy.md` §3, §5, §6.)
