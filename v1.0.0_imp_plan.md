# Bunyan v1.0.0 — Phased Implementation Plan

**Companion to:** `V1.0.0_spec.md` (and `core_logic.md`, `architecture.md`).
**Live status & handoff:** **`current_state.md`** — read it before starting work; it records what is already built and verified, and by whom.
**Revision:** **2026-07-12b** — incorporates the **agent-native rulings D19–D23** (spec §4.6). *Nothing in the phase order changes*, but three things move: **P2 gains the geometric query ops** (they must land before the protocol freezes at P3); **P3's registry/undo work is now the agent surface** (`argsSchema` on `Command`, the generated capability endpoint, `UndoableEdit` returned as a diff + a reserved transaction id, `window.bunyan`); and **P4 changes its wiring rule — Amer builds the shell against the COMMAND layer, never against `KernelClient` directly** (D19). ⚠ *This was cheap only because the document model, the registries and the command layer had not been written yet. It is a greenfield decision on the one unbuilt layer, not a retrofit — and it stops being cheap the moment P4 lands.*
**Prior revision:** **2026-07-12** — incorporates the owner rulings from building the real kernel (`current_state.md` Entries 3–7): the kernel is **our own upstream-OCCT 7.9.3 WASM build** with our C++ op set (**D14**, `opencascade.js` rejected); **v1.0.0 ships single-threaded** (**D8 reversed** — no COOP/COEP, no `SharedArrayBuffer`, one artifact); **IFC import is IfcOpenShell → exact solids** (**D16**, `web-ifc` rejected); a **`measure` op** is in the protocol (**D17**); and **Bunyan is AGPL-3.0 open source** (**D15**). Prior: 2026-07-11 (verification re-scoped to *"we trust OCCT; we verify our own code"*, golden seeding corrected to `cadquery-ocp`, box-discipline protocol added), 2026-07-08.
**Structure:** 7 phases, sequenced by dependency. Each phase lists an objective, the driving actor(s), concrete steps, and hard exit criteria (a phase is "done" only when its exit criteria pass in CI).
**Actors:** *Architect* (you) = interface contracts & scope; *Amer* (local PC, real browser) = browser hot path; *Zayd* (Hetzner CX23, headless) = kernel/WASM/Python/CI. See spec §12.

**⚠ Where the weight actually sits now (2026-07-12) — the phase order is unchanged, but two phases got heavier and one got lighter:**

| Phase | Change | Why |
|---|---|---|
| **P1** | **Much lighter — and largely DONE.** | The kernel is built and CI-gated; single-threading (D8) deleted the COOP/COEP headers, the second artifact and the capability detection outright. Only the Cloudflare deploy + service worker remain (Amer's). |
| **P2** | **Unchanged in scope, sharper in risk.** | Still the critical path and still the #1 risk — but we now know the naming model works on the *easy* case and have **not** yet touched the hard one (booleans/fillets). See the P2 status note. |
| **P6** | **⚠ MATERIALLY HEAVIER.** | IFC import was `npm install web-ifc` — a **library integration**. It is now **IfcOpenShell compiled and linked against our OCCT** (D16), i.e. **a second C++ build**, comparable in kind to the OCCT build itself. It is still correctly placed *after* the naming engine exists (imported solids must carry identities), but **it must not be estimated as an afternoon of wiring.** Budget it as kernel work. |
| **P3 / P4** | **⚠ AGENT-NATIVE (D19–D23) — no new phase, but a binding wiring rule.** | The agent surface is **not a feature bolted onto P7**; it is the P3 registry/command/undo work *done correctly*, plus a thin `window.bunyan` shim. **P4's rule changes: the React shell dispatches COMMANDS, and no React component ever holds a `KernelClient`** (spec §4.6.1). A "quick path" from the UI to the kernel would make every such capability permanently unreachable to an agent. **This is the one thing in this plan that gets expensive if it is discovered late.** |

**Split contract-freeze rule (spec §12, decision D13):**
- The kernel worker's **flat versioned message protocol** (spec §3, incl. the tessellation **provenance channel**) freezes at the **end of P3** so Amer/Zayd parallelize.
- The **`SubShapeRef` / `BimObjectType` / `Command`** contracts stay **release-candidate** through the start of P5; they freeze only **after Wall + Opening exercise them** (P5 steps 3, 5). This prevents freezing type contracts that only a trivial type has stressed.
- The Architect owns any change to a frozen contract.

**Critical-path mitigation (spec §12):** P1→P2→P3 is Zayd-heavy and serial. Zayd publishes a **kernel mock** (protocol-conformant fake worker returning canned meshes + provenance) at the start of P2 so Amer can build the P4 shell in parallel instead of idling.

## Phase 1 — Foundations & Toolchain

**Objective:** A reproducible build that compiles OCCT to WASM (**single-threaded**, D8), boots a kernel worker behind the versioned protocol, deploys a static shell to Cloudflare Pages with the offline service worker wired, and runs CI with the golden/invariant harness. No geometry *features* yet — this phase exists so every later phase has a green pipeline to land on.

**Status (2026-07-12): steps 1–5 and 8 are DONE and green; the kernel is real and gated by CI. Steps 6–7 (Cloudflare deploy + service worker) remain, and are Amer's.** See `current_state.md` §1/§3.

**Driver:** Zayd (build/WASM/CI), Architect (protocol contract), Amer (shell scaffold + service worker).

**Steps**
1. Initialize the repo: `git init`, TypeScript + React app scaffold (Vite), pnpm workspace, ESLint/Prettier, `tsconfig` strict mode.
2. Stand up the Python tooling env (`pyproject.toml`/uv) with **`cadquery-ocp`** (OCP bindings to a native OCCT build) for **offline** golden seeding only — not CI — on a **pinned, documented environment** (spec §6.5), build/orchestration scripts, and pre-commit hooks.
   *(Corrected 2026-07-11: the original step named **`pythonocc-core`**, which **cannot be installed** here — its PyPI entry is an abandoned `0.16` placeholder and the real 7.9.x releases are **conda-only**, while the box toolchain is `uv` (no conda, no system pip). `cadquery-ocp` wraps the same OCCT 7.9. **System dependency:** `libgl1` — OCP pulls in VTK, which links `libGL.so.1`; without it `import OCP` fails on a headless box.)*
3. **Build the kernel: upstream OCCT 7.9.3 → WASM, statically linked with our own C++ op set** (decision D14). **✅ DONE** — recipe in `tools/kernel-build/`, artifact committed at `packages/kernel-occt/wasm/` (**3.98 MB / 1.47 MB gzip**), build id `occt-7.9.3-emcc-6.0.2` (spec §6).
   - **ONE artifact, single-threaded** (D8). No multi-threaded build, no `SharedArrayBuffer`, no capability detection — all deferred to v1.0.x.
   - **`opencascade.js` is REJECTED and must not be retried** (D14). It **cannot be linked on this box at all**: its `-flto` object cache forces a whole-program-optimisation link that is OOM-killed even for a *6-symbol* build. It is also 3 years stale, exposes all of OCCT to JS, and — decisively — **forecloses linking IfcOpenShell** (D16).
   - **The two choices that made it build on a 3.7 GiB box:** **LTO OFF**, and **modelling toolkits only** (`BUILD_MODULE_Visualization/ApplicationFramework/DataExchange/Draw=OFF`). Keep `TKHLR` (hidden-line removal → plans/sections), `TKOffset` (wall layers), `TKShHealing` (repairing imports), `TKBO`/`TKBool`, `TKFillet`, `TKMesh`.
   - ⚠ **The heaviest run in the project** (Docker + emscripten, ~2.5 h). It **must** follow the **box-discipline protocol** below — the dev box hosts the owner's live public sites.
   - 🔑 **But changing the kernel's C++ is only a ~60-second rebuild** — OCCT's static libs are already built and cached on the box; `link.sh` compiles one `.cpp` and links. **Only an OCCT *version bump* costs 2.5 h.** Iterate freely.
4. Define the **flat, versioned kernel message protocol** (TS types + `protocolVersion`), including the **tessellation provenance channel** shape (per-triangle→face and per-edge→edge `SubShapeRef` maps, spec §3) and the **typed-failure** result envelope (spec §6.4). Implement an empty worker that handshakes, echoes, reports kernel version, and demonstrates a marshalled failure.
5. Wire transferable `ArrayBuffer` message plumbing (main ↔ worker) with a typed request/response dispatcher, correlation ids, and **edit-coalescing/cancellation** hooks (spec §3).
6. Configure Cloudflare Pages static deploy; verify `application/wasm` MIME type and that the kernel boots in the deployed context. **No `_headers`, no COOP/COEP, no `SharedArrayBuffer` check, no CORP audit** — v1.0.0 is single-threaded (D8), so none of it applies. *(It all returns in v1.0.x when MT lands — spec §13.)*
7. **Service worker + PWA (decision D11):** precache app shell + the chosen WASM artifact keyed by **build id**; Web App Manifest for install; verify the app loads and runs a kernel round-trip **fully offline** after one online load.
8. Stand up CI: build, typecheck, lint, unit-test stub, the **golden/invariant harness** (spec §9) that runs the WASM build and checks a known box against (a) committed **reference-build oracle** values (volume/area/length + counts, seeded offline from native OCCT), (b) **closed-form** values where a formula exists, and (c) **self-snapshot** values (mass checksums, adjacency hash), plus `Bnd_Box` bounds. **The OCCT-native Python oracle never runs in CI.** Scaffold the **re-seed gate** and the **first-load size/time budget check** on a throttled profile (spec §8).
9. ~~Capability detection (multi- vs single-threaded WASM)~~ — **CANCELLED for v1.0.0** (D8). There is one artifact. The kernel still reports its identity (`name`/`kernelVersion`/`buildId`/`threading`) at handshake, which is what the app and the BREP-cache-staleness check actually need.

**Exit criteria**
- ✅ CI green: TS build + golden/invariant harness pass on the known box against the **real kernel** (reference-build oracle **and** regression snapshot), bounds pass. *(First-load budget: pending the app.)*
- ⬜ Deployed shell on Cloudflare Pages loads the kernel worker, reports its build id, and **works offline after first load**.
- ✅ Kernel message protocol v1 documented and versioned, including the provenance channel and the typed-failure envelope.

## Phase 2 — Kernel Core & Persistent Naming Subsystem (D1, critical path)

**Objective:** The hardest item in v1.0.0 (spec §4.5). Expose OCCT primitives/booleans/fillets through the worker, emit **provenance-tagged** meshes, and make sub-shape references **survive rebuilds** via `SubShapeRef` (functional/generative naming; no OCAF/TNaming). Everything parametric depends on this, so it comes before the document model.

**Status (2026-07-12): step 0 done; steps 1, 5, 6, 8 done FOR THE EASY CASE ONLY.** `makeBox` + `measure` + `tessellate` + `releaseShape` are real, provenance-tagged, canonically re-sorted and CI-gated. **⚠ But naming has only been exercised on a box** — where the operation can simply name its own faces and every edge is bounded by exactly two named faces. **That assumption dies the moment a boolean runs.** Steps 1 (cylinder/prism/boolean/fillet), **4 (history coverage — do this FIRST)**, 7 and 9 are the remaining work, and they are the real risk.

**Driver:** Zayd (kernel + resolver + regression harness), Architect (`SubShapeRef` interface, release-candidate).

**Steps**
0. **Publish the kernel mock** (protocol-conformant fake worker) so Amer can start P4 in parallel (spec §12).
1. Implement worker commands for base geometry: make box/cylinder/prism, extrude a profile, revolve, boolean union/subtract/intersect, fillet/chamfer on an edge. Each returns a `BuildResult` (`ShapeHandle` on success, **typed failure** on OCCT failure — spec §6.4), never throwing across the boundary.
   - **✅ STATUS (2026-07-13, Entry 14): COMPLETE. `makeBox`, `makeCylinder`, `extrude`, `revolve`, `boolean`, `fillet`, `chamfer`, `transform` are ALL BUILT** — the first time this step's own list has actually matched the code. `revolve` (D27) was the last, and it is **not** the prism with a rotation: a full 360° turn has **no caps** (and OCCT's cap accessors do not return null for it — they return a face that is not in the result), every lateral face carries a **seam**, and **a segment perpendicular to the axis reports no history at all while its face sits in the result**. All three were **measured** (`probe.cpp` cases 12-15) before a line of the resolver was written.
   - ⚠ **A LESSON WORTH MORE THAN THE OPS.** `extrude` and `chamfer` sat in this step's scope, unbuilt, through **two sessions that both declared P2 complete** — and nothing caught it, because every test built its walls out of boxes. They were found by **modelling a building with the protocol** and discovering the floor plate was unbuildable: a **Slab** is *"planar boundary + thickness"* (spec §5) and a real plate is not a rectangle. **Checking this list against the code would have found it in a minute; nobody did, for a month.** Read the exit criteria as a *specification*, not as a summary of what was done.
   - ⚠⚠ **AND THE SAME LESSON, ONE LEVEL DEEPER, FROM ENTRY 14: the op set being complete does NOT mean the naming is.** Building `revolve` gave us a round column; cutting a duct through one — an ordinary service penetration — **was refused by the resolver**, because a round column's single wrap-around lateral face makes the duct's two rims *genuinely symmetric* (spec §4.5). **It had nothing to do with `revolve` and had been reachable since Entry 9 on a plain `makeCylinder`.** Nobody hit it because **every boolean ever tested cut a box.** ⇒ **An op list is not a shape list. Cut the shapes.** **✅ RESOLVED in Entry 15 by the owner's D28 ruling — the bounded positional key** (step 6 below). *The lesson stands regardless of the fix: the gap was found by cutting a shape nobody had cut, not by reading the op list.*
2. Implement a BREP (de)serializer for `geometry-cache.brep` and shape handles that survive worker round-trips; treat inbound BREP as **untrusted** on load (spec §9). Implement the **`ShapeHandle` registry / lifecycle** (explicit free of intermediates; heap telemetry — spec §6.2).
   - **Status (audited 2026-07-13, Entry 13): the `ShapeHandle` registry + lifecycle + heap telemetry are DONE. ⚠ THE BREP (DE)SERIALIZER WAS NEVER BUILT — ZERO CODE EXISTS** (the string `geometry-cache.brep` appears only in comments). **No entry ever said so.** It is nonetheless named in **`.bimproj`** (P3 step 4), the **cache-staleness** path (P3 step 5), and the **untrusted-BREP** security rule (§10).
   - ✅ **DECIDED 2026-07-13 — AND THE DECISION IS AN EXPLICIT DEFERRAL (D29), NOT A SILENCE.** The recipe is truth (`core_logic.md` §2), so the BREP cache is a **pure optimisation**: a document can always rebuild from `scene.json`. What it buys is **load time on a real building** — **a number that does not exist yet**, because there is no document model to measure it with. ⇒ **The owner ruled: decide at P3 step 4, WITH the measurement.** Until then **nothing may assume the file exists**, and every doc that claimed it now says so (spec §6, `architecture.md`, the security rule). ⚠ **If it is dropped, `.bimproj` must stop claiming the file and P3's exit criteria change** — that edit is part of the P3-step-4 decision, not an afterthought.
3. Define the opaque **`SubShapeRef`** interface (Architect, **release-candidate**) — structured path (`nodeId` + `role` + `occurrence`), never a raw OCCT index.
4. **⚠ VERIFY OCCT HISTORY COVERAGE FIRST — THIS IS THE NEXT TASK, AND IT IS EMPIRICAL (spec §4.5 caveat).** Before designing the general resolver, **find out what OCCT actually gives us**: confirm `Generated`/`Modified`/`IsDeleted` **edge/vertex** coverage for each needed operation — especially **a fillet on an edge produced by a boolean**, the hardest case. Add the C++ ops (`makeCylinder`, `boolean`, `fillet`) and *measure the history*, rather than designing against what the docs imply. Record which reference classes are safe; wrap or defer any with inadequate history (**never** fall back to geometric guessing). *(`TKBO`, `TKBool`, `TKFillet`, `TKOffset`, `TKShHealing` and `BRepTools_History` are all already in the build; the C++ rebuild is ~60 s.)*
5. Implement the **functional-naming propagation layer** in the worker (TypeScript): for each operation, read the maker maps and assign each output sub-shape an identity derived from the operation + its input identities. Graph is hybrid: coarse (feature) for history, fine (primitive-op) for propagation.
6. ✅ **DONE.** Implement the **structural tie-break** for 1→N splits/merges, with a **bounded positional key** (mm-rounded centroid, fixed rounding, spec §6.5) as the sole last resort for genuinely symmetric splits. **⚠ THE KEY WAS DELIBERATELY WITHHELD UNTIL A REAL MODEL NEEDED IT, AND THEN RULED IN BY THE OWNER (D28, 2026-07-13, Entry 15):** edges got their structural tie-break in Entry 9, faces in Entry 11 (a groove across a wall), and the **key itself** only when a duct through a **round column** produced two rims that no structural rule could separate. It is the **third** sort term — consulted only after derivation *and* structural signature have both tied — it **orders, never identifies**, and a collision on the mm grid is **refused**, not tolerated (§6.5). **It is the only place geometry touches the identity path.** Run every operation's `Generated`/`Modified` output through a **canonical re-sort** before assigning IDs, so **the kernel's traversal order can never leak into a name**. *(Note: v1.0.0 is single-threaded (D8), so the original multi-threading justification does not apply today — but **the re-sort still stands**, and it is the precondition for enabling MT in v1.0.x without invalidating saved files. Implemented for the box.)*
7. Implement the **rebuild engine**: persist the identity **token map**; on edit, rebuild only the affected subgraph and re-propagate identities; on load, deterministically replay to re-bind tokens. Mark a reference **broken** for **manual retargeting** (never silently reattach) when its target no longer exists.
   - **⚠ Status (audited 2026-07-13, Entry 13): NOT BUILT — and the BROKEN-REFERENCE STATE DOES NOT EXIST ANYWHERE.** `core_logic.md` **domain rule 3** and **§7** mandate `resolved ↔ **broken**`, with a broken reference being *"a first-class, visible state awaiting **manual retargeting**, never auto-healed."* **Today an unresolvable ref throws `UNRESOLVED_SUBSHAPE_REF` and the whole operation fails.**
   - ⇒ The promise *"predictable breakage beats silent wrongness"* is **half-kept**: the breakage is **loud** (good), but **a document cannot survive carrying one broken dependent**, and there is **no retarget path**. **Deleting a wall that a window is hosted on has no defined behaviour.**
   - ⚠ **This step is misfiled here. It is DOCUMENT-MODEL work and belongs in P3** — it needs the scene graph and the dependency DAG, neither of which exists in P2. **P5's Opening depends on it.** Do it in P3.
8. **Tessellation command with provenance**: convert a `ShapeHandle` to a mesh buffer (positions/normals/indices) **plus** the per-triangle→face and per-edge→edge `SubShapeRef` maps (spec §3) as transferables — display artifact + picking substrate.
9. Build the **persistent-naming regression suite**: "edit host parameters → assert dependent references re-resolve to the correct sub-shape, or correctly break." Include a large-extent model (spec §6.5). This is also the **reference-stability corpus** for the kernel-migration gate.
10. **✅ DONE (Entry 9) — THE GEOMETRIC QUERY OPS ARE IN, BEFORE THE FREEZE** *(decision D23/D25, spec §4.6.5)*. **`bounds`** (whole shape **or one NAMED sub-shape** — *"where exactly is the south face of that wall?"*, a question only persistent naming makes askable), **`distance`** (minimum separation + the two witness points — **zero doubles as the clash primitive**), **`classifyPoint`** (`inside`/`outside`/**`on`**). ⚠ **They read the B-Rep, never the mesh, and return millimetres and identities — never triangles**; a tessellated column is smaller than the real one by its chord error, so an agent reasoning about clearances from the mesh would under-report every clash in the project. **Implemented in BOTH kernels** — the mock answers them in closed form for a box, so the agent/query path is buildable with no wasm. **Document-level queries still need NO kernel op at all**: `getSceneGraph`/`getElementById`/filter-by-type read the **parametric recipe**, which is the truth (P3). **⚠ Placement (`at`) was added to the primitives in the same pass** — without it a boolean can only bite a *corner* off a wall, so a window in the middle was unreachable. **`transform` (rotation/mirror) is NOT in, and is the next op that will want in before the freeze.**

**Exit criteria**
- Boolean, extrude, revolve, fillet/chamfer match committed **reference-build-oracle values + regression snapshots + bounds** (spec §9).
- OCCT edge/vertex history coverage for every reference class shipped is documented and green in the naming suite.
- A fillet on an edge and an opening on a raw box face both **survive** a parameter change (reference re-resolves) in automated tests; an edit that removes the target correctly marks the reference broken.
- A known-failing operation (over-large fillet / open profile / empty boolean) returns a **typed failure** with no crash and no partial state (spec §6.4).
- Tessellation emits a correct mesh **and** a valid provenance map (a picked triangle resolves to the expected face `SubShapeRef`). ✅ *(box)*
- WASM heap returns to baseline after a rebuild cycle (no leak — spec §6.2), asserted against the **WASM module's own** live-handle count, not just the registry's. ✅
- **Role labels are honest** — the harness re-measures what each name actually refers to (spec §9.1). A mislabelled face passes every numeric check, so nothing else can catch it. ✅ *(box)*
- **The mock and the real kernel emit identical `SubShapeRef`s** for the same input, so swapping them is a no-op for the browser. ✅
- Kernel protocol extended, still flat/versioned. ✅ *(`measure` added — D17)*

## Phase 3 — Document Model, Registries & Persistence

**Objective:** The parametric "truth" layer above the kernel: the scene graph, the five registries (as empty, working extension points), the `.bimproj` format, local persistence, autosave/crash recovery, and load-time migration. **The protocol freezes at the end of this phase** (type contracts do not — decision D13).

**⚠ THIS PHASE IS ALSO THE AGENT SURFACE (D19–D23, spec §4.6).** There is **no separate "agent phase"** and there must never be one: the agent API *is* the Command registry, the capability endpoint *is* a projection of the registries, and the agent's diff *is* the `UndoableEdit`. Building P3 correctly *is* building the agent surface; building it carelessly means retrofitting it later against frozen contracts.

**Driver:** Amer (persistence, registries UI-side, `window.bunyan`), Architect (registry interfaces + migration + the agent contract), Zayd (BREP cache, query ops, schema generation).

**Steps**
1. Implement the document graph: `{id, typeId, params, levelId, transform, subShapeRefs[]}` nodes plus the persisted **naming token map** (spec §6), and dependency tracking (which node depends on which host) to drive incremental rebuild.

   > ### ⚠ ONE SOLID PER ELEMENT. NEVER FUSE TWO ELEMENTS INTO ONE SOLID. *(measured, Entry 12)*
   >
   > **What happens if you do:** fuse two walls that meet at a corner and **only 2 of the first wall's 6 faces keep their identity.** The rest are re-owned by the *fuse* — `wall-s/face/y-min#0` becomes `corner-sw/face/fuse(wall-s.face.y-min~0+wall-w.face.y-min~0)#0`. That is **correct** (a merged face genuinely *is* a new face derived from two parents) and it is **catastrophic** at the document level: **every window hosted on that wall breaks the moment a neighbour is joined to it**, and it breaks *retroactively*, on a wall nobody edited.
   >
   > **The rule:** a boolean is an **intra-element** operation — an element's own recipe (its base solid, minus the openings hosted on it, plus its own sub-parts). An **L-shaped slab built as a fuse of two boxes is fine** (one element, one `nodeId`, one recipe). **Wall + wall is not.** Each element owns exactly one solid, built from its own parameters, and nothing outside it may re-own its faces.
   >
   > **Corner joins, wall-to-wall cleanup and double-counted corner volume are a QUANTITIES/DISPLAY concern, not a geometry one** — and they are **v1.0.x**. Do not reach for a fuse to solve them.
2. Implement the five registries as runtime registries with typed contracts (spec §4): BIM Object Type, Command/Action, File Format Codec, View/Representation, and the Persistent Naming resolver binding. Ship them **empty but exercised** by one trivial test type/command (contracts still **release-candidate**).
   - **⚠ `Command` carries an `argsSchema`** *(D21)*, exactly as `BimObjectType` carries a `parameterSchema`. This is the field that makes the agent's tool list **generated rather than maintained** — and it is far cheaper to put in the contract now than to add after the P5 freeze.
   - **⚠ `DocumentContext` is the ONLY holder of a `KernelClient`** *(D19)*. Enforce it — a lint rule or a package boundary, not a comment. If any other module can import the kernel client, the rule is already broken.
3. Implement the **undo/redo stack as `UndoableEdit` state deltas** with reference re-resolution (spec §6.1) — not command replay; wire it into the edit-coalescing budget.
   - **`execute` RETURNS the `UndoableEdit`** *(D23)* — the delta undo needs and the diff an actor verifies against are the same object.
   - **Reserve the transaction id** on `UndoableEdit` *(D23)*: edits sharing one undo/redo as a single all-or-nothing unit. **v1.0.0 emits one edit per command and does NOT implement grouping** — the field exists because the contract freezes at P5 and every composite verb (v1.0.x) will need it.
3a. **Implement the agent surface** *(D19–D23, spec §4.6)* — small, because everything it needs already exists by step 3:
   - **The capability endpoint**: `listCommands()` / `listTypes()`, **generated** from the registries (never hand-written — D21).
   - **The read/query API**: `getSceneGraph` / `getElementById` / filter-by-type-or-level, reading the **recipe** (no kernel op needed). ⚠ **It returns SEMANTICS — ids, types, params, levels, quantities, relationships — never triangles.** A `Float32Array` is unreadable to an agent. Register it as a **View/Representation** (spec §4.4): the projection *for reasoning*, alongside the 3D projection *for eyes*.
   - **`window.bunyan`** *(D22)*: `version` / `listCommands` / `listTypes` / `execute` / `query`. A **thin shim over the Command registry** — if it needs any logic of its own beyond marshalling, D19 has been violated somewhere upstream. **Zero install; no backend.** *(MCP bridge = v1.0.x, another transport over the same verbs.)*
   - **Version the surface separately** (`agentApi: 1`) *(D22)* — independent of `protocolVersion` and of the P5 type-contract freeze.
   - **⚠ Agent-issued commands opt OUT of edit-coalescing** *(D23)* — a `SUPERSEDED` failure is meaningless to an agent that issued one deliberate command. Coalescing belongs to interactive input, not to commands.
4. Implement the `.bimproj` zip package: `manifest.json` (app/schema/OCCT-build-id/per-type versions), `scene.json`, optional `history.json`, `thumbnail.png`. **No `export.ifc`** in v1.0.0 (decision D3).

## Phase 4 — Rendering & Interaction Shell

**Objective:** Turn kernel meshes into an interactive 3D scene and give the app its UI skeleton — all generated from the registries so new types/commands appear without hand-wiring. **Starts against the P2 kernel mock as soon as the protocol freezes.**

> ### ⚠ THE WIRING RULE FOR THIS PHASE (decision D19 — read before writing a line of React)
>
> **Every UI action dispatches a COMMAND. No React component may hold a `KernelClient`.**
>
> ```
>   button / drag ─┐
>   agent verb ────┼──►  Command registry ──► DocumentContext ──► KernelClient ──► OCCT

> ```

If no Command expresses it, the UI does not do it.**
>
> ⚠ **The `KernelClient` sample in `current_state.md` §5 shows the kernel being driven directly.** That sample is correct as a *kernel* integration proof and **wrong as an app architecture** — it predates D19. Use it to understand the kernel; **do not use it as the shape of the app.**

**Driver:** Amer (browser hot path).

**Steps**

4. Selection & picking, including **sub-shape picking** (face/edge) that maps a picked triangle/edge to a `SubShapeRef` **via the provenance map** (spec §3) — the input side of P2's naming system.

6. **Auto-generated property panel** driven by each type's `parameterSchema` (spec §4.1); editing a parameter dispatches an `UndoableEdit` (debounced/coalesced) and triggers rebuild + re-tessellation; **surface typed operation failures** as dismissible errors (spec §6.4).

## Cross-cutting practices (all phases)

- **Contract-first, split-freeze:** never edit a frozen contract without Architect sign-off. The message protocol freezes at P3; type contracts freeze after Wall+Opening in P5 (decision D13). New features are additive registry entries (spec §4). The **`agentApi` surface is versioned separately** and does not inherit the P5 freeze (D22).
- **⚠ ONE COMMAND LAYER — the rule with no exceptions (D19, spec §4.6).** Every action, from every actor, is a Command. **`DocumentContext` is the only holder of a `KernelClient`** — enforce it with a machine check, not a convention. A capability reachable only through the UI is a capability an **agent can never have**, and nobody finds the gap until an agent is asked to use it. **A new command is an agent verb automatically** (its `argsSchema` generates the tool definition — D21); there is **no separate agent feature list to keep in sync**, by construction. ⚠ **An agent must never be handed a kernel op** (`makeBox`, `tessellate`): that would create a solid **no entity owns, no undo can remove and no `SubShapeRef` names.**
- **Snapshot-gated geometry:** no new `buildGeometry` merges without passing the **reference-build-oracle** checks (volume/area/length + counts, via the exact **`measure` op** — D17, never off the mesh) **and** the **regression snapshots** (mass checksum, adjacency hash) **and** committed **re-seeded goldens** on the pinned env (spec §9). The re-seed rule fails geometry changes that lack them. Verification is scoped by spec §9.0: **we trust OCCT; we verify our own code** — and every bug the harness has caught so far has been *our misreading of an OCCT API*, never an OCCT defect.
- **⚠ Naming is verified AS NAMING.** A mislabelled sub-shape passes every numeric check — the geometry is exact and only the *names* are wrong (it has already happened: four of a box's six faces). Any new op must assert **what its names actually refer to**, not just that its volume is right.
- **Kernel-migration gate:** a change to the **kernel build id** (`occt-<version>-emcc-<version>`) within 1.0.x must replay the reference-stability corpus and fails if any `SubShapeRef` re-resolves differently. **Re-seed the goldens whenever OCCT itself moves** — the oracle (`cadquery-ocp`) and the WASM build must stay on the *same* OCCT version, or the harness is comparing two different kernels.
- **Failure-safe kernel:** every worker op returns a typed `BuildResult`/`CommandResult`; OCCT failures never crash the tab, never produce a partial edit (spec §6.4).
- **Memory discipline:** explicit `ShapeHandle` lifecycle; no rebuild leaves leaked WASM heap (spec §6.2).
- **Offline-first:** every release ships a working service-worker cache keyed by build id (spec §8).
- **CI stays green + first-load budget:** every phase lands on a green pipeline; a broken golden/invariant, naming, import-fidelity, or first-load-budget check blocks merge.
- **Actor placement:** display-dependent work runs where a real browser exists (Amer/local); kernel/WASM/Python/CI runs headless (Zayd/Hetzner); Amer works against Zayd's kernel mock until P2 lands.
- **Risk watch — two risks now, not one, and both are Zayd-concentrated kernel work:**
  1. **P2, Persistent Naming (D1) — still the #1 schedule risk.** ⚠ **And do not be reassured by the green box.** Naming currently works on the *easy* case: `makeBox` names its own faces, and every edge is bounded by exactly two named faces. **A boolean breaks that assumption**, and today the kernel deliberately *refuses* to name what it cannot derive structurally — which is the right failure mode and also a wall you hit on the first cut. The real work (history coverage for booleans/fillets) has **not started**. If the general resolver stalls, apply the spec §4.5 fallback contract — but do **not** ship v1.0.0 until `SubShapeRef` is real, since retrofitting it would break `scene.json`.
  2. **P6, IFC import (D16) — a NEW risk, created by a good decision.** Choosing exact solids over triangles means IfcOpenShell must be **compiled and linked against our OCCT**: a second C++ build, not a library integration. This was the right call (triangles break the core invariant, `core_logic.md` §3.5) and it is only *possible* because we own the kernel (D14) — but it moved a chunk of C++ build work into a phase that used to be mostly wiring. **Estimate it as kernel work.** *(Mitigation available and cheap: spike the IfcOpenShell link early — even during P2 — to find out whether it builds at all against our toolchain. Discovering it does not, in P6, would be very expensive.)*

### Box-discipline protocol for heavy runs *(owner ruling, 2026-07-11 — binding)*

**Context a new agent must not have to discover the hard way:** Zayd's dev box is small (**~3.7 GiB RAM + 2 GiB swap**) **and it is simultaneously the production host for two live public sites.** The OCCT→WASM build (Docker + emscripten), large IFC parses, and big benchmarks are all capable of exhausting it. An out-of-memory event here does not just fail a build — it can **take the owner's public websites offline.**

**The rule: never run anything that would overload the box.** Before any heavy run:

1. **Check headroom** (`free -h`) and **constrain the run itself** — cap Docker memory, cap compiler parallelism (`-j`). A build that cannot balloon cannot take the box down.
2. **Free memory by pausing other projects' NON-production services.** The owner has **pre-authorized** pausing work belonging to projects he is not actively using: **Planitor** (`planitor-pg`), **Chantier_Manager** (`chantier_test_pg`, `chantier_test_redis`), **Portique_Designer** (no containers), **SmartBar**. Graceful `docker stop` only — **never** `kill`, **never** `rm`, **never** remove a volume. Check that project's `current_state.md`/handoff for active work first.
3. **NEVER touch production. These are not pause targets under any circumstance, including box strain:**

   | Container | What it is | Why it is untouchable |
   |---|---|---|
   | `portfolio-caddy-1` | Caddy on **:80/:443** | Serves the **live** `beam-stack.com` and `daoudi.beam-stack.com`. Stopping it takes both public sites offline. |
   | `beamstack-contact` | Lead-capture service | Handles **real inbound leads** and sends visitor-facing email. Stopping it drops real business enquiries. |

   These are light apps that use the dev box **as their production box**. They are cheap to leave running and expensive to interrupt — the opposite of the trade-off that justifies pausing anything else.
4. **Restore what you paused** the moment the heavy run ends, and verify it is healthy. ⚠ `chantier_test_pg` / `chantier_test_redis` are `restart=no` — they will **not** come back on their own.
5. **Record the pause + restore** in the box-local `last_session_work.md`.

**If a run cannot be made safe by the above, do not run it — escalate to the owner** with the memory numbers and the options. (Full box rules: the box-local `cross_projects_policy.md` §3, §5, §6.)
