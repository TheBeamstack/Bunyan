# Bunyan v1.0.0 — Phased Implementation Plan

**Companion to:** `V1.0.0_spec.md` (and `core_logic.md`, `architecture.md`).
**Revision:** 2026-07-08 — aligned to the reviewed spec (IFC import-only, offline PWA, operation-failure contract, split verification, split contract-freeze, provenance-carrying tessellation).
**Structure:** 7 phases, sequenced by dependency. Each phase lists an objective, the driving actor(s), concrete steps, and hard exit criteria (a phase is "done" only when its exit criteria pass in CI).
**Actors:** *Architect* (you) = interface contracts & scope; *Amer* (local PC, real browser) = browser hot path; *Zayd* (Hetzner CX23, headless) = kernel/WASM/Python/CI. See spec §12.

---

## Dependency overview

```
P1 Foundations & Toolchain
        │
P2 Kernel Core + Persistent Naming (D1, critical path)   ── protocol mock published early ──┐
        │                                                                                     │
P3 Document Model, Registries & Persistence  ── freezes PROTOCOL only ──►  P4 can start against mock
        │                                                                                     │
   ┌────┴─────────────────────────────────────────────────────────────────────────┐         │
P4 Rendering & Interaction  ◄───────────────────────────────────────────────────────┘◄───────┘
        │   (P4 starts against the kernel mock as soon as the protocol is frozen at P3;
        │    P4 and P5 overlap)
P5 MVP Object Types & Commands  ── Wall+Opening validate & FREEZE type contracts (spec §12, D13) ──►
        │
P6 2D Views & IFC Import
        │
P7 Hardening, Performance, Offline & Release
```

**Split contract-freeze rule (spec §12, decision D13):**
- The kernel worker's **flat versioned message protocol** (spec §3, incl. the tessellation **provenance channel**) freezes at the **end of P3** so Amer/Zayd parallelize.
- The **`SubShapeRef` / `BimObjectType` / `Command`** contracts stay **release-candidate** through the start of P5; they freeze only **after Wall + Opening exercise them** (P5 steps 3, 5). This prevents freezing type contracts that only a trivial type has stressed.
- The Architect owns any change to a frozen contract.

**Critical-path mitigation (spec §12):** P1→P2→P3 is Zayd-heavy and serial. Zayd publishes a **kernel mock** (protocol-conformant fake worker returning canned meshes + provenance) at the start of P2 so Amer can build the P4 shell in parallel instead of idling.

## Phase 1 — Foundations & Toolchain

**Objective:** A reproducible build that compiles OCCT to WASM (both multi-threaded and single-threaded), boots an empty kernel worker behind the versioned protocol, deploys a static shell to Cloudflare Pages with the offline service worker wired, and runs CI with the split golden/invariant harness. No geometry features yet — this phase exists so every later phase has a green pipeline to land on.

**Driver:** Zayd (build/WASM/CI), Architect (protocol contract), Amer (shell scaffold + service worker).

**Steps**
1. Initialize the repo: `git init`, TypeScript + React app scaffold (Vite), pnpm workspace, ESLint/Prettier, `tsconfig` strict mode.
2. Stand up the Python tooling env (`pyproject.toml`/uv) with `pythonocc-core` (for **offline** golden seeding only — not CI) on a **pinned, documented environment** (spec §6.5), build/orchestration scripts, and pre-commit hooks.
3. Build OCCT → WASM via OpenCascade.js: produce **both** artifacts — the **multi-threaded** build (needs `SharedArrayBuffer`, decision D8) and the **single-threaded** fallback. Pin the OCCT/OpenCascade.js version and record its **build id** (spec §6). Confirm the multi-threaded build's `BOPAlgo` parallelism is actually active (not silently single-threaded).
4. Define the **flat, versioned kernel message protocol** (TS types + `protocolVersion`), including the **tessellation provenance channel** shape (per-triangle→face and per-edge→edge `SubShapeRef` maps, spec §3) and the **typed-failure** result envelope (spec §6.4). Implement an empty worker that handshakes, echoes, reports kernel version, and demonstrates a marshalled failure.
5. Wire transferable `ArrayBuffer` message plumbing (main ↔ worker) with a typed request/response dispatcher, correlation ids, and **edit-coalescing/cancellation** hooks (spec §3).
6. Configure Cloudflare Pages static deploy + `_headers` (COOP `same-origin`, COEP `require-corp`); verify `SharedArrayBuffer` is enabled in the deployed context and the single-threaded fallback boots when it is forced off; verify `application/wasm` MIME; **audit that all cross-origin assets are CORP-compatible**.
7. **Service worker + PWA (decision D11):** precache app shell + the chosen WASM artifact keyed by **build id**; Web App Manifest for install; verify the app loads and runs a kernel round-trip **fully offline** after one online load.
8. Stand up CI: build, typecheck, lint, unit-test stub, the **split golden/invariant harness** (spec §9) that runs the WASM build and checks a known box against (a) committed independent-oracle values (volume/area/length + counts) and (b) self-snapshot values (mass checksums, adjacency hash), plus `Bnd_Box` bounds. **No pythonocc in CI.** Scaffold the **re-seed gate** and the **first-load size/time budget check** on a throttled profile (spec §8).
9. Capability detection: on boot choose multi- vs single-threaded WASM and expose the result to the app.

**Exit criteria**
- CI green: TS build + split golden/invariant harness pass on the known box (independent oracle **and** regression snapshot), bounds pass, first-load budget met.
- Deployed shell on Cloudflare Pages loads the kernel worker, reports version, confirms `SharedArrayBuffer` (and falls back cleanly when forced off), and **works offline after first load**.
- Kernel message protocol v1 documented and versioned, including the provenance channel and typed-failure envelope.

## Phase 2 — Kernel Core & Persistent Naming Subsystem (D1, critical path)

**Objective:** The hardest item in v1.0.0 (spec §4.5). Expose OCCT primitives/booleans/fillets through the worker, emit **provenance-tagged** meshes, and make sub-shape references **survive rebuilds** via `SubShapeRef` (functional/generative naming; no OCAF/TNaming). Everything parametric depends on this, so it comes before the document model.

**Driver:** Zayd (kernel + resolver + regression harness), Architect (`SubShapeRef` interface, release-candidate).

**Steps**
0. **Publish the kernel mock** (protocol-conformant fake worker) so Amer can start P4 in parallel (spec §12).
1. Implement worker commands for base geometry: make box/cylinder/prism, extrude a profile, revolve, boolean union/subtract/intersect, fillet/chamfer on an edge. Each returns a `BuildResult` (`ShapeHandle` on success, **typed failure** on OCCT failure — spec §6.4), never throwing across the boundary.
2. Implement a BREP (de)serializer for `geometry-cache.brep` and shape handles that survive worker round-trips; treat inbound BREP as **untrusted** on load (spec §9). Implement the **`ShapeHandle` registry / lifecycle** (explicit free of intermediates; heap telemetry — spec §6.2).
3. Define the opaque **`SubShapeRef`** interface (Architect, **release-candidate**) — structured path (`nodeId` + `role` + `occurrence`), never a raw OCCT index.
4. **Verify OCCT history coverage first (spec §4.5 caveat).** Before building the general resolver, empirically confirm `Generated`/`Modified`/`IsDeleted` **edge/vertex** coverage for each needed operation — especially fillet-on-an-edge-produced-by-a-boolean. Record which references are safe; wrap or defer any with inadequate history (never fall back to geometric guessing).
5. Implement the **functional-naming propagation layer** in the worker (TypeScript): for each operation, read the maker maps and assign each output sub-shape an identity derived from the operation + its input identities. Graph is hybrid: coarse (feature) for history, fine (primitive-op) for propagation.
6. Implement the **structural tie-break** for 1→N splits/merges, with a **bounded positional key** (mm-rounded centroid, fixed rounding, spec §6.5) as the sole last resort for genuinely symmetric splits. Run every operation's `Generated`/`Modified` output through a **canonical re-sort** before assigning IDs, so multi-threaded boolean ordering is deterministic (decision D8).
7. Implement the **rebuild engine**: persist the identity **token map**; on edit, rebuild only the affected subgraph and re-propagate identities; on load, deterministically replay to re-bind tokens. Mark a reference **broken** for **manual retargeting** (never silently reattach) when its target no longer exists.
8. **Tessellation command with provenance**: convert a `ShapeHandle` to a mesh buffer (positions/normals/indices) **plus** the per-triangle→face and per-edge→edge `SubShapeRef` maps (spec §3) as transferables — display artifact + picking substrate.
9. Build the **persistent-naming regression suite**: "edit host parameters → assert dependent references re-resolve to the correct sub-shape, or correctly break." Include a large-extent model (spec §6.5). This is also the **reference-stability corpus** for the kernel-migration gate.

**Exit criteria**
- Boolean, extrude, revolve, fillet/chamfer match committed **independent-oracle values + regression snapshots + bounds** (spec §9).
- OCCT edge/vertex history coverage for every reference class shipped is documented and green in the naming suite.
- A fillet on an edge and an opening on a raw box face both **survive** a parameter change (reference re-resolves) in automated tests; an edit that removes the target correctly marks the reference broken.
- A known-failing operation (over-large fillet / open profile / empty boolean) returns a **typed failure** with no crash and no partial state (spec §6.4).
- Tessellation emits a correct mesh **and** a valid provenance map (a picked triangle resolves to the expected face `SubShapeRef`).
- WASM heap returns to baseline after a rebuild cycle (no leak — spec §6.2).
- Kernel protocol extended to v2, still flat/versioned.

## Phase 3 — Document Model, Registries & Persistence

**Objective:** The parametric "truth" layer above the kernel: the scene graph, the five registries (as empty, working extension points), the `.bimproj` format, local persistence, autosave/crash recovery, and load-time migration. **The protocol freezes at the end of this phase** (type contracts do not — decision D13).

**Driver:** Amer (persistence, registries UI-side), Architect (registry interfaces + migration), Zayd (BREP cache).

**Steps**
1. Implement the document graph: `{id, typeId, params, levelId, transform, subShapeRefs[]}` nodes plus the persisted **naming token map** (spec §6), and dependency tracking (which node depends on which host) to drive incremental rebuild.
2. Implement the five registries as runtime registries with typed contracts (spec §4): BIM Object Type, Command/Action, File Format Codec, View/Representation, and the Persistent Naming resolver binding. Ship them **empty but exercised** by one trivial test type/command (contracts still **release-candidate**).
3. Implement the **undo/redo stack as `UndoableEdit` state deltas** with reference re-resolution (spec §6.1) — not command replay; wire it into the edit-coalescing budget.
4. Implement the `.bimproj` zip package: `manifest.json` (app/schema/OCCT-build-id/per-type versions), `scene.json`, `geometry-cache.brep`, optional `history.json`, `thumbnail.png`. **No `export.ifc`** in v1.0.0 (decision D3).
5. Implement load-time **migration**: per-type `version` migration functions, and cache-staleness handling (rebuild from `scene.json` when OCCT build id differs or cache is missing/corrupt/untrusted).
6. Implement persistence mechanisms (spec §7): File System Access API (save/save-as + stored handle; **one-click "resume saving" re-grant on a fresh session**, spec §7 correction), universal zip-download/`<input file>` fallback, OPFS scratch for the geometry cache, IndexedDB for autosave/undo/settings/handles.
7. Implement **autosave & crash recovery**: lightweight snapshot (`scene.json` + BREP cache only) to OPFS/IndexedDB on interval and after every N edits, capped ring (~5); request `navigator.storage.persist()`; recovery prompt on next boot.
8. **Freeze the message protocol** (incl. provenance channel + failure envelope) and tag it; publish the protocol doc. Keep `SubShapeRef`/`BimObjectType`/`Command` marked **release-candidate**.

**Exit criteria**
- Round-trip: create a document with the trivial test type → save `.bimproj` → reload in a fresh session → identical parametric state and geometry (and a working "resume saving" re-grant).
- Corrupt/delete `geometry-cache.brep` → document still loads by rebuilding from `scene.json`; a hostile BREP cache fails safe.
- Autosave recovers an unsaved session after a simulated crash.
- A simulated type-version bump triggers migration and the old file still loads.
- **Message protocol tagged frozen**; type contracts documented as release-candidate.

## Phase 4 — Rendering & Interaction Shell

**Objective:** Turn kernel meshes into an interactive 3D scene and give the app its UI skeleton — all generated from the registries so new types/commands appear without hand-wiring. **Starts against the P2 kernel mock as soon as the protocol freezes.**

**Driver:** Amer (browser hot path).

**Steps**
1. Integrate three.js `WebGPURenderer` with automatic WebGL 2 fallback; verify both backends boot on the deployed build.
2. Build the tessellation pipeline: kernel mesh buffers → three.js `BufferGeometry`; **retain the provenance maps** alongside each geometry; incremental re-tessellation on edits; dispose/regenerate meshes as pure display artifacts.
3. Camera controls (orbit/pan/zoom — never blocked on the kernel), grid, world axes; world coordinates in **millimeters** (spec §6).
4. Selection & picking, including **sub-shape picking** (face/edge) that maps a picked triangle/edge to a `SubShapeRef` **via the provenance map** (spec §3) — the input side of P2's naming system.
5. React app shell: layout, viewport, panels; **ribbon/toolbar generated from the Command registry** `contributesUI` descriptors (spec §4.2).
6. **Auto-generated property panel** driven by each type's `parameterSchema` (spec §4.1); editing a parameter dispatches an `UndoableEdit` (debounced/coalesced) and triggers rebuild + re-tessellation; **surface typed operation failures** as dismissible errors (spec §6.4).
7. Custom shading via **TSL** (compiles to WGSL + GLSL) — basic shaded/edged display; no raw GLSL, no legacy `EffectComposer`.
8. Wire undo/redo to keyboard + UI and confirm the viewport reflects state-delta undo correctly.

**Exit criteria**
- The trivial test type renders, is selectable (a specific face/edge → valid `SubShapeRef` via provenance), and its parameters are editable through the auto-generated panel with live geometry update; a forced operation failure shows a clean error and no partial edit.
- Ribbon shows exactly the registered commands — adding a stub command makes it appear with zero UI edits.
- Renders correctly on both WebGPU and WebGL2 (visual regression from this phase on).

## Phase 5 — MVP BIM Object Types & Commands

**Objective:** The actual authoring feature set (spec §5): six MVP object types + the full MVP command set, each a registry entry, each verified by the split golden/invariant harness. **Wall + Opening validate and then FREEZE the type contracts (decision D13).**

**Driver:** Amer (commands/interaction/sketching UI) + Zayd (each type's `buildGeometry` + golden/invariant test), Architect (type/param semantics, scope, contract sign-off).

**Steps**
1. **Level / Story** type first (organizing scaffold): elevation-based grouping + object-to-level assignment.
2. 2D sketching commands: line, rectangle, circle, arc, with **numeric dimension entry** and **profile validation** (closed, non-self-intersecting before extrude/revolve — spec §5.2).
3. **Wall** (extrude + boolean), **Slab/Floor** (planar boundary + thickness), **Column** (rect/circular profile extrude) — each with `defaultParams`, `parameterSchema`, `ifcMapping` (import side), optional `quantities` stub, golden/invariant test. **Wall is the first real stress-test of the `BimObjectType` contract.**
4. **GenericSolid** (free sketch + extrude/revolve) — escape-hatch type and unmapped-IFC import target.
5. **Opening**: boolean-subtracted void hosted on a Wall/Slab **via `SubShapeRef`** (the P2 payoff), carrying the **anchoring parameter** (`fixed`/`proportional`/`centered`, decision D12); verify it survives host edits under each anchoring mode. **Opening is the first real stress-test of `SubShapeRef` in a document context.**
6. **⟶ FREEZE `SubShapeRef` / `BimObjectType` / `Command`** now that Wall + Opening have exercised them; Architect signs off; tag the type contracts frozen (spec §12, D13).
7. Editing commands: **extrude, boolean, fillet/chamfer** (fillet persisted via `SubShapeRef`), **move, rotate, copy, array (linear/grid)**; each produces a proper `UndoableEdit` and a typed failure path.
8. Command-level unit tests against a mock `DocumentContext` (incl. failure paths) for each command; golden/invariant tests for each type; confirm no core edits were needed to add any of them (additive-principle evidence).

**Exit criteria**
- A user can model a simple building end to end: place levels, draw and extrude walls, add a slab and columns, cut an opening, edit a wall's length and watch the opening (per its anchoring mode) + fillet re-resolve correctly.
- Every MVP type passes its split golden/invariant test; every MVP command passes its unit + failure-path test.
- **Type contracts frozen** after Wall+Opening validation; adding the last type/command required no edit to core scene-graph/undo/persistence code (recorded as evidence).

## Phase 6 — 2D Views & IFC Import

**Objective:** Prove the kernel is the single source of truth by generating 2D views as *real cuts* of the real geometry, and achieve IFC4 **import** through the codec registry. (IFC **export** is deferred — decision D3.)

**Driver:** Zayd (section-cut kernel op + IFC importer + import corpus), Amer (2D view rendering + import UI), Architect (IFC mapping validation).

**Steps**
1. Implement the **section-cut** kernel operation: cut the actual B-Rep at a plane, extract profile curves (not a separate drafting engine — spec §5.2).
2. Register a **plan view and one elevation** in the View/Representation registry (spec §4.4) rendering the cut profiles; link them live to the 3D document graph. (The elevation exercises a non-horizontal cut plane.)
3. Implement the **IFC importer** (web-ifc) against the Codec registry: **import = mapped-or-GenericSolid** — recognized IFC types (`IfcWall`/`IfcSlab`/`IfcColumn`/`IfcOpeningElement`) map to native parametric types; everything else imports as GenericSolid with geometry preserved (non-parametric).
4. Make the IFC-schema binding an **abstraction** (`IfcSchemaVersion`) so the future **exporter** and IFC5/IFCX are later sibling registrations, not rewrites (decision D3).
5. Build the **IFC import-fidelity corpus**: seed from web-ifc's public test models + Bunyan-authored `.bimproj` samples; run import fidelity (geometry + type mapping within tolerance) in CI. *(Full export round-trip is a v1.0.x gate.)*
6. Validate IFC import mappings with the Architect (AEC correctness) for each MVP type.
7. **Harden import**: decompression size/ratio caps + entry-count limits on `.bimproj` zips, IFC schema validation, parsing inside the worker with a timeout — malformed/hostile files fail safe without hanging or OOM-ing the tab (spec §9).

**Exit criteria**
- A plan view and a (non-horizontal) elevation are generated as genuine section cuts of the live model and update when the model changes.
- A representative IFC4 model imports with geometry + type fidelity within tolerance (mapped-or-GenericSolid), and the import corpus passes in CI.
- Malformed/hostile `.bimproj`/IFC inputs fail safe (no hang/OOM/crash).

## Phase 7 — Hardening, Performance, Offline & Release

**Objective:** Make it robust, fast at BIM scale, cross-browser, offline-capable, and shippable — then release v1.0.0.

**Driver:** All three; Zayd leads release engineering, Amer leads browser/perf/visual-regression/offline, Architect owns scope sign-off.

**Steps**
1. Cross-browser matrix: Chromium (full FSA API + multi-thread) and the universal fallback path (Firefox/Safari: download/upload save, single-thread where needed); confirm the **single-threaded WASM fallback** boots with the "reduced performance" notice (spec §8).
2. Performance at scale: GPU-side culling/instancing (compute shaders / TSL) for thousands of repeated elements; measure and set large-model budgets (tessellation time, memory/heap ceiling, save latency) and confirm the **first-load size/time budget** (spec §8) is met in CI.
3. Incremental rebuild optimization: only rebuild/re-tessellate the affected subgraph on edits, using P3 dependency tracking; validate edit-coalescing/cancellation under rapid drag.
4. **Offline/PWA hardening (decision D11):** verify service-worker cache invalidation on a build-id bump, offline cold-start, and update flow; confirm both WASM artifacts are cache-covered.
5. **Visual regression** against **both** WebGPU and WebGL2 backends (`renderer.info`/`stats-gl`) — O5.
6. Resilience pass: corrupt-cache recovery, broken-reference retargeting UX (spec §4.5), operation-failure UX polish (spec §6.4), capped-ring autosave limits, migration edge cases, WASM heap ceiling behavior.
7. Accessibility, keyboard shortcuts, empty/error states, minimal in-app onboarding for the end-to-end flow.
8. Release engineering: version tagging, `manifest.json` schema/version finalization, **kernel-upgrade policy — OCCT upgrades within 1.0.x allowed only behind the migration gate replaying the reference-stability corpus** (spec §9), production Cloudflare Pages pipeline (preview → production), asset preload/streaming, licensing/attribution review (spec §11).
9. Final regression run (split golden/invariant + persistent-naming + IFC-import + operation-failure + command unit + visual + first-load budget) all green → tag **v1.0.0** and deploy.

**Exit criteria**
- Full end-to-end task passes on Chromium and on at least one non-Chromium browser via the fallback path; app works **offline after first load** with correct update-on-new-build behavior.
- Single-threaded fallback verified; large-model performance + first-load budgets met.
- All test suites green in CI (split geometry harness, persistent-naming, IFC-import fidelity, operation-failure, command unit, visual regression on both backends).
- v1.0.0 tagged and live on Cloudflare Pages, matching every principle in spec §1.

## Cross-cutting practices (all phases)

- **Contract-first, split-freeze:** never edit a frozen contract without Architect sign-off. The message protocol freezes at P3; type contracts freeze after Wall+Opening in P5 (decision D13). New features are additive registry entries (spec §4).
- **Split-verification, snapshot-gated geometry:** no new `buildGeometry` merges without passing the **independent-oracle** checks (volume/area/length + counts) **and** the **regression snapshots** (mass checksum, adjacency hash) **and** committed **re-seeded goldens** on the pinned env (spec §9). The re-seed rule fails geometry changes that lack them.
- **Kernel-migration gate:** an OCCT/OpenCascade.js upgrade within 1.0.x must replay the reference-stability corpus and fails if any `SubShapeRef` re-resolves differently.
- **Failure-safe kernel:** every worker op returns a typed `BuildResult`/`CommandResult`; OCCT failures never crash the tab, never produce a partial edit (spec §6.4).
- **Memory discipline:** explicit `ShapeHandle` lifecycle; no rebuild leaves leaked WASM heap (spec §6.2).
- **Offline-first:** every release ships a working service-worker cache keyed by build id (spec §8).
- **CI stays green + first-load budget:** every phase lands on a green pipeline; a broken golden/invariant, naming, import-fidelity, or first-load-budget check blocks merge.
- **Actor placement:** display-dependent work runs where a real browser exists (Amer/local); kernel/WASM/Python/CI runs headless (Zayd/Hetzner); Amer works against Zayd's kernel mock until P2 lands.
- **Risk watch:** Phase 2 (Persistent Naming, D1) is the schedule risk, concentrated on one actor. If the general resolver stalls, apply the spec §4.5 fallback contract — but do **not** ship v1.0.0 until `SubShapeRef` is real, since retrofitting it would break `scene.json`.
