## 2. The fixture, and the two things it had to be built around

8 storeys · 88 elements · 112 solids. Per storey: a closed rectangular ring of four baseline walls (all
eight ends miter against exactly one partner), four free-standing partitions that touch nothing, and three
doors hosted on the ring's south wall.

**(a) Baseline `{start,end}` walls, never the `{length,height}` fixture.** `baselineOf` returns
`undefined` for the legacy fixture wall, so `resolveJoins` early-returns and the join question — the one
thing that could have made lazy build unsafe — would never have fired. This is the same trap
`P5_step9_D66_scale_design.md` §1 already flagged about the existing scale harnesses.

**(b) Each storey's ring is offset 60 m in plan**, to work around the level-scoping defect in §6. Without
the offset every corner in the fixture would have carried fifteen coincident endpoints, the ambiguity
fallback would have dropped every miter, and §2's join measurement would have been of nothing.

**(c) Doors on every storey, not only on level 0.** A hosted void is by far the most expensive element
here (a void extrude, a boolean through the host, two leaf solids). Putting them all on one storey — the
first shape of this fixture — left every sweep point carrying the same fixed lump of door work, which is
half of why the first sweep was unusable (§4).

## 3. The safety condition, measured

Two cold `DocumentContext`s from the **same `.bnn` bytes**, one `rebuildAll()`, one
`rebuildOnly(keepLive)`, compared element for element and part for part over the 9 elements built in both:
part names and order, `Part.nodeId`, `Part.refs` and `quantities()` volume/area all identical (quantities
to 1e-6); `brokenRefs()` empty in both.

**Across a join — the case that could have made lazy build unsafe.** The keep-live set deliberately omits
two of the four ring walls, so the built south wall's `start` corner meets a west wall the partial
document never builds. `resolveJoins` is a pure function of the `Scene` and reads no built state:

```
resolveJoins(scene, south)  partial ['start','end']   full ['start','end']
bounds(south)               partial [-100,-100,0 … 8100,100,3000]
                            full    [-100,-100,0 … 8100,100,3000]
```

The `-100` is the miter reaching 100 mm past the baseline start; a jointless cap starts at `0`. **The
miter is present although its partner was never built.**

⚠ **The comparison is made on `bounds`, not on `refs`, and that is deliberate.** T-011 measured a mitered
and an unmitered cap carrying byte-identical sub-shape tokens — `refs` cannot see a miter, and a join
assertion written on it would be a weak green.

## 4. The deferral numbers, and the two measurement defects found getting to them

| | |
| --- | --- |
| deferred, by element | 89.8 % (9 of 88 built) |
| deferred, by solid | 89.3 % (12 of 112 built) |
| `rebuildAll()` | 2443 ms |
| `rebuildOnly(keepLive)` | 347 ms |
| cold load removed | 85.8 % |

Sweep of `rebuildOnly` at 22 / 44 / 66 / 88 elements → 707 / 1231 / 1869 / 2567 ms, fresh warm kernel
each, OLS of ms on elements: **slope 28.3 ms/element, intercept 39 ms (1.6 % of the full load), R²
0.9961.** A second run gave 27.3 ms / 84 ms / R² 0.9991, so the slope is stable to ~4 % and the fixed part
is small either way. ⇒ the deferrable fraction in elements and in wall-clock agree to within ~4 points, so
the keep-live set's size is the whole story.

⚠ **28.3 ms/element is this fixture's cost, not the cost at scale.** Its walls are single-layer; T-004's
richer fixture measured 41.9–43.8 ms/element. The doc says so beside the number, because the tempting
misuse is to quote it as a per-element figure.

**Two measurement defects, both found by the instrument failing rather than by reading it:**

1. **A four-point sweep on cold kernels produced a NEGATIVE marginal cost** (`expected -0.759 to be
   greater than 0`): each later load was warmer than the one before by more than its extra elements cost.
   Fixed by building and freeing one throwaway element on each kernel before the clock starts — which is
   also the honest model of the product, where the kernel is constructed once at bootstrap long before a
   `.bnn` is opened.
2. **With the warm-up but with all the doors on level 0**, the fit came back R² **0.2539**, slope
   0.81 ms/element, intercept 432 ms — the marginal was below the noise because every sweep point carried
   the same door work. Fixed by (c) above; R² went to 0.9961.

⚠ Neither was visible from reading the harness. Both are why the sweep exists at all: a single
partial-vs-full pair gives an element fraction and a wall-clock fraction that disagree, with no way to say
which part of the cost is fixed.

**`rebuildOnly` carries no penalty for being bounded**: at the top sweep point it builds the whole model in
2567 ms against `rebuildAll()`'s 2443 ms — the same work within the run-to-run spread. That is the
evidence for §4 of the doc: the build half needs **no new API**.

## 5. §3c — what a partially built document reports

`projectQuantities()` **DECLARES**: 12 rows and 79 `unmeasured` entries against the full load's 112 and 0.
Nothing is silently dropped.

⚠⚠ **But the reason is wrong for every one of the 79.** `enumerate.ts:215` gives an element with no
geometry entry `state: 'failed'` and `failure: 'unbuildable'` — what a Type refusing to build looks like —
so a consumer cannot tell *"nobody has asked for this yet"* from *"this cannot be built at all"*. Under
lazy build a normal first paint becomes a take-off reporting most of the building as broken. This is the
load-bearing item T-005 inherits, whichever way its FORCE/DECLARE choice goes; `ElementState.stale`
already means *recipe present, solid not built*.

**`save` does not read built state — measured, not asserted.** The two documents' scenes are byte-identical
as JSON, and `saveBnn(scene, options)` takes a `Scene`, never a `DocumentContext`, so there is no built
state within its reach. ⚠ **This discharges T-005's first `done-when:` bullet**, which asks that this be
measured before anything else is chosen; that bullet was written expecting T-018 to leave it a claim.
T-005's actual choice — FORCE or DECLARE per aggregate — is untouched and still owed.

## 6. ⚠⚠ The unplanned finding: wall joins are not level-scoped

`partnersAt`/`throughWallsAt` match baselines in 2D, and `indexOf` indexes every element in the scene
carrying a baseline; none of the three consults `containerId`, the level's elevation, or the wall's
base/top datums. Measured through the shipped verbs on the real OCCT kernel, one storey then the same
corner one level up:

```
one storey   resolveJoins(a) = ['start']   bounds(a).min.x = -100
two storeys  resolveJoins(a) = []          bounds(a).min.x =    0
```

The crowd of coincident endpoints reads as ambiguous, the auto-miter falls back to the plain cap, and a
wall on a storey nobody edited changes shape. Two walls stacked at the same plan position on different
storeys is the ordinary case in any multi-storey building, so this is not an edge case — it is D68's
ambiguity flip arriving through elevation instead of through design options.

Recorded in `docs/BACKLOG.md ## Discovered` with a fix shape (scope the scans to walls sharing a vertical
extent, using datums `baselineOf`/`elevationOf` already resolve). **Not claimed** — `AGENTS.md §3`.

against `nodeId`, which is what the criterion means. Changing `identitiesOf` from `parts.flatMap(p =>
[...p.refs])` to `parts.map(p => p.nodeId)` and re-running left **1 of 8 RED**:

```
× ⚠⚠ every element built in BOTH carries byte-identical sub-shape identities
  → the identity signature must carry more than the recipe-derived node ids: expected 12 to be greater than 12
```

⚠ **Note what stayed green through that revert, because it is the whole point of the tripwire:** the
element-for-element identity comparison itself. `partNodeId` is `${elementId}.${partName}`, a pure function
of the recipe computed with no kernel call, so a partial and a full build agree on it whatever the geometry
did — the agreement check reading it passes on an input it exists to refuse. The tripwire is the assertion
that the compared signature carries more than the node names do, and it is the half that goes red.
Restored: 8/8 green.
