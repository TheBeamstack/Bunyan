## 2. F1 — the suite's 951 green is not evidence for this fix

**The finding of this turn.** §7 correctly says re-seeding cannot detect this change, then adds that *"the
suite, which drives the real kernel — 951 green"* is what exercises the patched glue. That reads as
assurance and is not one. Measured, with the pre-patch glue in the tree and the whole suite run:

```
 Test Files  1 failed | 97 passed (98)
      Tests  2 failed | 949 passed (951)
```

**2 of 951 tests detect this defect**, and both are the new text-scanning assertions in
`tests/kernel-glue-growable-decode.test.ts`. Every golden passes on the defective glue — `golden-box`,
`golden-extrude`, `golden-revolve`, `golden-transform`, `golden-hard-geometry`: **40 passed** — as does every
other test that drives the real WASM kernel through this glue.

The cause is §9's own measurement, reproduced here on Node 20.20.2:

```
rab.resizable                      = true
subarray().buffer.resizable        = true
slice().buffer.resizable           = false
node WASM memory.buffer.resizable  = false
node decodes RESIZABLE-backed subarray ok = true
```

Node's WASM buffer is not resizable and Node decodes a resizable-backed view without complaint, so the suite
**exercises** the glue but **cannot discriminate** patched from unpatched. The headless evidence for this PR is
a text scan of the artifact plus a semantics probe, and nothing else.

§9 states the underlying limitation accurately; §7's sentence should be brought in line with it before merge.
**This is not a code defect** — the fix is correct. Its consequence is that **T-023 is load-bearing rather than
a formality**, which is the opposite of how a reader skimming "951 green" would price it.
