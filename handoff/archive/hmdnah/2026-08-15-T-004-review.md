## 2. Why the old assertion could not bite (REVIEW.md item 6 — weak green)

`ElementGeometry.state` is `'valid' | 'failed' | 'broken-ref'`, and `geometryOf` returns `undefined` for
an element that has never been built:

```ts
expect(cold.geometryOf(id)?.state, `${id} did not rebuild`).not.toBe('failed');
```

`undefined !== 'failed'`, so the check whose message reads _"did not rebuild"_ passes precisely when the
element did not rebuild. `brokenRefs()` is the same shape of hole from a different direction — it returns
`scene.brokenRefs`, a **stored** field of the loaded scene, so it reports what `save` wrote rather than
what the rebuild found.

The replacement counts through `partsOf`, which reads built geometry, so it is a statement about the
build and not about the file.

## 8. The approval could not be cast at first — and what the owner ruled

`REVIEW.md` §1.2 routes an approving, green, `RISK: additive` PR to the reviewer's own merge, on the
account that did not open it. That account is not on this box.

```
$ gh auth status
  ✓ Logged in to github.com account Davidian-Abdo
$ gh pr review 20 --approve
failed to create review: GraphQL: Review Can not approve your own pull request
```

`Davidian-Abdo` is the account `zayd` opened #20 from. `narutousomaki741` exists here only as
`git config user.name` / `user.email` (`narutousomaki741@example.com`) — authorship metadata, never a
GitHub identity, and the address is not real. So the second party that makes `gh pr review --approve` a
genuine cross-account act (`AGENTS.md §0`, D82) is unavailable to this seat.

⚠⚠ **GitHub's refusal is the only thing that caught this, and it does not guard the dangerous half.**
`gh pr merge` is not blocked for a repo admin merging their own PR, so a reviewer turn that reaches for
the merge command `agent-finish.mjs` printed — without checking who it is authenticated as — lands
exactly the Entry 74 self-merge that `AGENTS.md §6` says is not optional twice. It went unnoticed until
now because #18 and #19 were merged by the owner, so no reviewer seat had ever reached the approve step.

`AGENTS.md §3` calls this Blocked: precondition failed ⇒ stop, and record it in the PR and in the entry's
`OWES:`. Both were done, plus a `## Discovered` row, and the turn stopped there with the backlog row
returned to `review` — `done` means merged, which `agent-finish.mjs --review` had already optimistically
written.

**Resolved the same day, by owner ruling, env-scoped rather than global.** A `narutousomaki741` PAT
(`repo`, `workflow`, `read:org`; `push=true`) lives at `~/.config/bunyan/hmdnah.token`, mode 600, and a
seat exports `GH_TOKEN=$(cat …)` for the duration of its own turn:

```
$ GH_TOKEN=$(cat ~/.config/bunyan/hmdnah.token) gh api user --jq .login
narutousomaki741
$ gh api user --jq .login          # unset — the box's default is unchanged
Davidian-Abdo
```

Choosing the account per turn instead of `gh auth switch` is what keeps two seats on one box from
inheriting each other's identity. #20 was then approved and merged on `narutousomaki741`.

⚠⚠ **The durable rule, which the ruling does not itself enforce: a reviewer confirms `gh api user` is its
own seat's account before approving or merging.** GitHub refuses a self-approval and that is the only
reason this was caught; it does **not** refuse a repo admin merging their own PR. A seat that exports no
token and reaches straight for the merge command `agent-finish.mjs` prints still lands the Entry 74
self-merge, silently.
