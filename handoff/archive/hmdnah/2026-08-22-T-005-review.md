## 3. NEW KIND OF THING

`stale` is a new member of `ModelElement.state`. What quantifies over "every one of them" is
`deferredElements`, and the invalidator is `#forceBuild` → `rebuildOnly`. Checked:
`rebuildOnly` passes `rejectOnFailure = false`, so FORCE **cannot** turn a read-only aggregate into a
D42 rejection when a deferred element's kernel build refuses — the one failure mode that would have
made every take-off throw on a bad element. `UnmeasuredElement.reason` is `string`, so the widened
union reaches no type surface. Nothing switches exhaustively on the union.

## 4. CLAIMS vs CODE

Read against the code, not the entry: `agent.ts:151` does already answer `?? 'stale'`, so the
"two roads disagreed" argument is true. `ElementGeometry['state']` is `'valid' | 'failed' | 'broken-ref'`
— `stale` genuinely is the member it cannot carry. `unbuildable()` does read the geometry map, so a
never-built element was never in its reach.

⚠ **One claim narrower than stated.** *"`saveBnn` … no built state is within its reach"* is true of its
signature, and the byte-identity it rests on holds only because the fixture has **no broken refs**:
`scene.brokenRefs` is a build output that `#commit` writes **into the Scene**, and `saveBnn` persists it.
A partially built document therefore saves a shorter `brokenRefs` than a fully built one. It self-heals,
because the primary load path is `rebuildAll` and `#stage` re-derives the entry — so `NEITHER` is still
the right ruling, and the argument for it is *"the one built field it reaches is re-derived on load"*
rather than *"it reaches none"*. Pre-existing, unchanged by this PR, and already half-stated in the
entry's own §5.

## 9. THE DEFECT CI PROVED, AND THIS TURN FIXED

⚠⚠ **`pnpm verify` green on the box is not the same claim as green CI, and this PR is where the two
disagreed.** The first push went red on the self-hosted runner:

```
FAIL tests/d66-lazy-build-measure.test.ts > D66 lazy build — the instrument the design doc is written
  from (T-018) > ⚠⚠ §3c — the enumeration DECLARES the deferred elements `stale`; `projectQuantities` FORCES
Error: Test timed out in 5000ms.
 Tests  1 failed | 958 passed (959)
```

**Cause, and it is this PR's own change.** The turn rewrote that §3c case (handoff §8) so it now calls
`projectQuantities()` on the partial document — which, after this same PR, **FORCES a whole-model
rebuild**. The case therefore stopped being a pure read and became real OCCT work, while keeping the
5 s default; the file's own `beforeAll` already carries `900_000` for exactly that reason.

**Measured both sides:** the forced take-off runs in **3892 ms on this box** and over **5000 ms on the
CI runner** — a margin of about a second, which is the worst possible place for a threshold to sit,
because the machine decides the verdict. The author cannot have seen it: `pnpm verify` is green here.

⇒ Fixed on the branch: an explicit `120_000` timeout on that one case, with a comment saying it builds
and why the default does not apply. Green here at 8 passed, and the whole point of the number is that it
no longer depends on which machine runs it.

⚠ The PR's own new file, `tests/d66-force-declare.test.ts`, is **not** affected — it uses a small
fixture and passed on the runner in the same job.
