## 3. New kind of thing

The new kind is the **entry identity** (`EntryAbstract.key`, `number | string`). The question is what
quantifies over every one of them, and in particular whether the **acceptor** agrees with the
**writer** — because a writer that can mint a value its own gate refuses is Q15's disease reproduced
inside the machinery built to cure it.

**Writer** → `state.mjs --rebaseline` → `baselineSnapshot({ entry: newestAbstract(...).key })`.
**Acceptor** → `baselineEntryIssues` → `ENTRY_KEY` / `isSyntheticEntryNumber`.

Quantified over every heading in `current_state.md` §7 + `docs/history.md`, not over §7 alone
(`scratchpad/keycover.mjs`):

```
headings: 42 new-scheme, 13 legacy
keys the writer can mint that the acceptor REFUSES: 0
headings matching neither regex: 0 abstract headings (27 hits are prose ### headings and the
                                 pre-D82 `### Entry NN — …` archive form, which §7 never holds)
```

**Clean, and it is clean by construction rather than by luck:** `ENTRY_KEY`'s three alternatives are
byte-identical to `NEW_HEADING`'s capture groups 1, 3 and 4, so `abstractKey`'s output cannot leave
the acceptor's language. That is the check this item exists for and it is the strongest part of the
diff.

Two boundary results, neither blocking:

- **G3 — the synthetic-position guard is sized to a cap §7 exceeds in normal operation.**
  `isSyntheticEntryNumber` covers `(990, 1000]`, i.e. §7 indices 0–9. A turn appends its abstract
  *and then* rotates, so §7 transiently holds 11; index 10 mints `n = 990`, for which the guard
  returns **false** — a position accepted as a legacy entry number. Unreachable through the writer
  today (`state.mjs` writes `.key`), so it is a gap in a guard whose stated job is *"the position
  cannot come back through the file it was written into"*, not a live hole.
- **The collision count, quantified:** 4 colliding keys of 51 distinct, over §7 + history — the same
  four step 1 lists. See item 2's F1/F2 disposition below for what is wrong about how that is
  recorded.

**The invalidator.** `diffSurface(baseline.surface, buildSurface('.'))` — the thing that actually
decides `RISK` — never reads `_baselinedAtEntry`. Re-measured on the tip: `{added:[], removed:[],
changed:[]}`, 214 = 214. The identity change cannot reach the risk verdict, which is the right
separation and is why this PR is `additive` while touching the frozen-surface file.

### G5 — `--review --step 2` stamps `done` on an owner-gated PR

`agent-finish.mjs` decides the backlog flip with `seats.reviewFlipsToDone(risk, step,
contractTouching)`, and `contractTouching` is read from §8's frozen-surface row — `additive` here.
`reviewFlipsToDone('high', 2, false)` ⇒ **`true`**, so this turn's finish writes `T-024 → done` while

This is T-014's defect one class over. `AGENTS.md §5` names **three** owner-gated classes and

freeze class and the legal-figure class both walk past it. The 2026-08-18 `## Discovered` row covers
the *printed merge commands* half of this — a command a human can decline — and not the row flip,
which no human sees. Fix shape: `--review` resolves the reserved classes it already has a module for
and keeps the row `review` whenever any `needs-operator/*` applies, which is the same correction the
printed-commands row asks for, at the one call site that writes state.

**I set the row back to `review` by hand after the finish script ran**, which is correct for two
