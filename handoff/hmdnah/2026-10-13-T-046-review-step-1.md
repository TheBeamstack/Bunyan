  offset `+20` was rewritten to `ceil(8 MiB / 100)`. So done-when 2's "a high-ratio entry … makes loadBnn throw"
  holds only for an honest header, and the comment "DEFLATE's ceiling is ~1032:1, a bomb's ratio" is not
  enforced. The same holds in `cache.read`. Allocation stays bounded by the size caps (256 MiB per entry,
  512 MiB total, which is the fflate claim below). What the cap fails to stop is amplification: 512 MiB from a
  file of about 0.5 MB. Fix: bound each entry's declared compressed size by the bytes the file holds for it
  (from its local data start to the next local header, or to the central-directory offset). Write the probe
  above as the test first.
