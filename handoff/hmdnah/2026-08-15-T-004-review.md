## 2. Why the old assertion could not bite (REVIEW.md item 6 — weak green)

`ElementGeometry.state` is `'valid' | 'failed' | 'broken-ref'`, and `geometryOf` returns `undefined` for
an element that has never been built:

```ts
expect(cold.geometryOf(id)?.state, `${id} did not rebuild`).not.toBe('failed');
```

`undefined !== 'failed'`, so the check whose message reads _"did not rebuild"_ passes precisely when the
element did not rebuild. `brokenRefs()` is the same shape of hole from a different direction — it returns
`scene.brokenRefs`, a **stored** field of the loaded scene, so it reports what `save` wrote rather than
what the rebuild found.

The replacement counts through `partsOf`, which reads built geometry, so it is a statement about the
build and not about the file.

## 5. The red CI, fixed at its writer

PR #20's only CI failure was `format:check` (CI step 3) on `docs/BACKLOG.md`, a defect already recorded in
the backlog's `## Discovered`: `agent-finish.mjs`'s `setRowStatus` wrote the longer word `review` into a
cell padded for `ready` and kept the old trailing spaces, so the column changed width and
`prettier --check` rejected it. Nothing in the author's own diff was at fault.

Repadding the cell on this branch alone would not have held: the same function writes `done` at the end of
a review turn, and preserving a cell's committed width is only correct once that width is correct. So the
fix is in the writer, as the `Discovered` note itself asks — `setRowStatus` is hoisted to module scope,
exported, and repads to the width it found. Revert-verified:

```
- | T-001 | review  | x     |
+ | T-001 | review   | x     |
 ❯ tests/protocol/agent-finish.test.ts:161:37
```

which is the exact byte CI rejected on #20. The new case also asserts every row of the table stays the
same length as its header, so a future status word of a different length cannot reopen this.

title, leaving #16 and #17 unclaimable — is **not** touched here. It is explicitly reserved for a
