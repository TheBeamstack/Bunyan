## 3. Flag one — derived at the query rather than staged

**Correct, and the code proves the reason.** `#stage` (`document.ts:1165`) keeps
`scene.brokenRefs.filter(b => scene.elements[b.elementId] !== undefined && !roots.includes(assemblyRoot(scene, b.elementId)))`,
so an entry survives untouched whenever its element's assembly is not a rebuild root. A staged option
entry would therefore outlive the tag that produced it — a wall tagged `ghost` keeps its entry after
`core.createDesignOption` defines `ghost`, because that command does not make the wall a rebuild root.
That is D74's defect, and the same line's comment (*"exactly one producer and it reads `scene.elements`"*)
is the invariant a second producer would have broken.

**Cost, measured rather than assumed.** `brokenRefs()` now walks `scene.elements` on every call, so I timed
it on a hand-assembled 10,000-element scene (the D48 binding target), 20 calls per configuration:
**3.288 ms/call with one element tagged, 3.822 ms/call with all 10,000 tagged.** It has one non-test call
site, `App.tsx:415`, inside a `useMemo` keyed on `[app, version]` — once per document version, beside
`unbuildable()`, which is already an O(N) walk at the same site. Affordable.

## 5. The one finding — domain rule 3's contract text, fixed on the branch

`docs/contracts/core_logic.md` describes a broken reference in one class only: *"a `SubShapeRef` it depends
on could not be resolved"* (§7 state table) and *"awaiting **manual retargeting**"* (rule 3). This PR ships
a second class, and **no verb can clear it** — `core.createElement` is the only writer of `designOptionId`
(the sweep of `commands.ts` returns one write site), and neither `core.retargetReference` nor
`core.setElementMetadata` touches the field.

That meets rule 3's own D74 sweep note head-on: *"A refusal nobody can act on has stopped being a refusal
and become a lie about the model's state."* The PR satisfies it, but for a reason the contract does not
record: because the entry is **derived and never stored**, it enters no `.bnn` and clears the moment the
option resolves, so it cannot become the permanently-dirty document D74 measured. Deriving at the query is
therefore load-bearing for rule 3, not only for staleness.

Contracts win over an entry's prose (`AGENTS.md §2`), and a contract narrower than the code is the defect
`AGENTS.md §3` row 1 says to fix rather than code around. Added one sentence to rule 3 naming the second
class, its lack of a retarget road, and the derivation that keeps it actionable. `docs/contracts/` is
`.prettierignore`d, so `format:check` is unaffected.
