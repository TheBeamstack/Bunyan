## Changed

- `packages/document/src/bnn.ts`: four exported caps (`BNN_MAX_ENTRIES` 40,000, `BNN_MAX_ENTRY_BYTES`
  256 MiB, `BNN_MAX_TOTAL_BYTES` 512 MiB, `BNN_MAX_RATIO` 200:1, the ratio checked only above 1 MiB).
  `checkEntry` refuses naming the cap. `loadBnn` runs `checkCaps` first, a central-directory pass whose
  filter returns `false` for every entry; `geometryCacheReader.read` checks inside its single filter,
  because the reader keeps the caller's bytes rather than a copy.
- `tests/bnn-zip-caps-t046.test.ts` (new, 7 tests).

## Verified

- Allocation is bounded by declared sizes: fflate 0.8.3 `unzipSync` inflates into `new u8(originalSize)`
  with resize off (`esm/index.mjs:2704`, `:241`); a stored entry copies only bytes the file holds.
- Calibration at 16k (`node`: 16,000 walls + 16,000 `.brep` of 3,817 B, `zipSync` level 6): 16,001 entries,
  67,204,691 B inflated, largest `scene.json` 6,132,691 B; ratios `scene.json` 33.5:1, `.brep` 3.5:1,
  50 MB of zeros 1024.6:1. Two of these are corrected under `## Returned`.
- Test-first: `pnpm exec vitest run tests/bnn-zip-caps-t046.test.ts` before `bnn.ts` → 5 failed, 2 passed;
  after → 7 passed. Revert-verify: the `index >= BNN_MAX_ENTRIES` check removed → 1 failed (entry cap).
