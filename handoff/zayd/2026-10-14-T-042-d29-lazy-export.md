## Changed

- `packages/document/src/cacheexport.ts` (new): `exportAssembly` exports one live assembly's solids, or
  `undefined` if any member is not `valid`, a hosted element has no geometry, a member has a broken ref, or the
  kernel refuses mid-export.
- `packages/document/src/document.ts`: optional `DocumentOptions.geometryCacheEnvelope` (defaults to
  `geometryCache.current`). `#stage` reports built vs restored roots, and `#commit` queues each built root and
  forgets any export of a root rebuilt, restored or deleted. `exportCacheIdle(max)` exports queued roots and
  keys each one against the scene it lands in. If an edit replaced the root's live geometry during the export,
  the result is dropped. `geometryCacheFiles()` is synchronous and calls no kernel op. It recomputes every key
  and writes an idle export whose key matches. A restored or never-built root is carried from the file
  (`usableRecord`), never a built one.
- `packages/document/src/cacherestore.ts`: `usableRecord` (the key and well-formedness check, shared by
  restore and carry) and `recordEntries`.
- `packages/document/src/bnn.ts`: `GeometryCacheReader.readMany`, one zip pass for many entries, with the
  same per-entry caps. `read` is now `readMany([name])`. A carry at 16k through `read` would be O(n²).
- `tests/geometry-cache-export-d29.test.ts` (new, real OCCT, R3's fixture: 5 assemblies, 20 solids), with 8
  tests plus 1 env-gated 16k measurement.

## Measurement

Command: `BUNYAN_D29_MEASURE_16K=1 pnpm exec vitest run tests/geometry-cache-export-d29.test.ts -t measures
--disable-console-intercept`. This session could not run an env-prefixed command without approval, so the
figures below come from the same test with its `runIf` condition set to `true` locally, then restored.

- Method: the fixture's 20 real exported solids are replicated assembly by assembly to 16,000 under fresh root
  ids, then `saveBnn` is timed best of 3 with and without the cache. Sizes are read from the zip's central
  directory.
- `.brep`: 2,747 B/solid raw and 687 B compressed (4.00:1), which is 43.9 MB / 11.0 MB at 16k.
- `index.json`: 3,830 B/solid raw and 228 B compressed (16.80:1), which is 61.3 MB / 3.6 MB at 16k, in one
  entry.
- `saveBnn`: 4,141 ms with the 16k cache and 0.3 ms without it. At 20 solids the figures are 5.1 ms / 0.3 ms.
- The T-046 caps hold at 16k: 105 MB inflated is under 512 MiB, the largest entry (61 MB) is under 256 MiB, and
  the worst ratio (16.8:1) is under 200:1. No cap moved.
- What this does not show: the mix is curtain-wall heavy (D59 child rows in the index), and this is not a real
  16k model.
