## 3. FOUND

### 3a. ⚠⚠ THE GATE Q16 IS ABOUT HAD NEVER EXECUTED THE PATH I WAS CHANGING, AND MY UNIT TESTS WOULD NOT HAVE NOTICED.

Entry 73 established that `check-reseed.mjs` had never once run its real path in 73 entries. I wrote
six unit tests over the new helpers, and then — because of that history — ran the gate itself in a
throwaway git repo. **Revert-verification #5 is the finding:** with the gate's body reverted to its
pre-Q16 form, the *unit* tests stayed green and **so did both source-text "is it wired?" assertions**,
because the reverted gate still *contained* the strings `goldenValuesMoved(` and `confirmationIn(` —
below an early `process.exit(0)`. Only the end-to-end test went red.

⇒ **A wiring assertion that greps the source proves the call is WRITTEN, not that it RUNS.** It is
strictly weaker than it reads, and Entry 80 introduced two of them (in good faith — they are much
better than nothing). Where the artifact can actually be executed, execute it:
`tests/reseed-gate-e2e.test.ts` builds a repo, commits the four scenarios, and asserts the **exit
code**, which is the only thing CI reads.

### 3b. ⚠⚠ BOTH DEFECTS FAIL OPEN, AND THAT IS NOT A COINCIDENCE — IT IS WHAT AN UNTESTED GATE DRIFTS TOWARDS.

A gate is written by someone who wants their own PR to pass. Every shortcut that makes the gate quieter
is invisible in the session that takes it and expensive three entries later:

- `--rebaseline` sets `risk = 'additive'` — *technically* true after the write, and the reason it is
  wrong is that **the only PR that ever runs `--rebaseline` is a PR that moved the frozen surface.**
  The flag inverted the label on exactly the population it applied to.
- the re-seed gate asks *"was the file touched?"* because that is a `git diff --name-only` away, while
  *"did anything CHANGE?"* needs both sides read and parsed.

⇒ **Ask what the population of a check actually is.** A rule whose exception clause covers its whole
population is not a rule.

### 3c. ⚠ THE CONFIRMATION HAD TO COST A SENTENCE, OR IT WOULD BE THE TIMESTAMP AGAIN.

An unmoved payload is a legitimate outcome — Entry 79's byte-identical relink is the worked example,
and it *should* move no golden. So the gate cannot simply refuse; it needs a way to say *"yes, and here
is why."* Three mechanisms were considered:

| mechanism | why not |
| --- | --- |
| an env var / CI input | set once in a workflow file and true forever after; invisible in the diff |
| a marker file | says nothing, and rots in the tree |
| **a commit trailer with a REASON** | lands in the history beside the diff it excuses, is reviewable, and must be re-written every time |

`Re-seed-unchanged:` with nothing after it does **not** match (`/^Re-seed-unchanged:\s*(\S.*)$/im`) —
that is revert-verification #4. The gate prints the reason back into the log, so a reviewer reads a
claim rather than a checkmark.

### 3d. ⚠ `_baselinedAtEntry` IS THE `OCCT_BUILD_ID` DISEASE WITH NOT EVEN A SELF-ASSERTION.

Entry 79's lesson was *when a constant must describe something, ask WHO COMPUTES IT.* Here nobody did:
the writer spread `...prev` and overrode the three fields it remembered. The number now comes from the
same `current_state.md` §7 parse the run already performs — and because `newestAbstract` **throws** on a
failed parse (Entry 80), a session that cannot read §7 no longer gets to rewrite the freeze baseline
either. That ordering is free and it is the good kind of coupling.

⚠ The committed `72` is corrected **by hand, once**, to `77` — which `git log tests/frozen-surface.snapshot.json`
identifies as the entry that actually wrote it (`7da794d`). A test asserts it, so the correction is part
of this diff rather than a promise about the next rebaseline.

### 3e. ⚠ WEAK-GREEN, CAUGHT IN MY OWN TEST BEFORE IT SHIPPED.

*"A bumped `seededAt` alone is not a re-seed"* passes if `payloadHash` strips **too much** — hash the
empty object and every golden matches every other golden. The pair of assertions is the fix: one
direction requires the clock to be ignored, the other requires a moved `volume` to be caught. Either
alone is satisfiable by a broken hash.

⚠ frozen-surface baseline REWRITTEN (212 declarations, entry 81).
  newest entry 81 · RISK: contract-touching (re-baselined)      ← correct

Measured against this branch with one baseline hash perturbed to simulate a moved declaration. §8's

⚠ It biases toward `contract-touching` in the one ambiguous case (a stale local `origin/main`). That is

### 7e. ⚠ NOT A DEFECT — THE ONE OPINION, RECORDED AND NOT BLOCKING

§3c argues the confirmation must **cost a sentence**, and it does. But apply §3b's own test to §3c: what
is the *population* of PRs that reach the trailer? Two members — *"the relink genuinely moved nothing"*
(Entry 79, legitimate) and *"the seeder never actually ran"* (the hazard the gate exists for). The gate
cannot tell them apart, so it hands the decision to the author — the party §3b has just finished arguing
is unreliable, *"because a gate is written by someone who wants their own PR to pass."* The improvement
is real (a sentence is reviewable; a timestamp is not), but the claim *"silence is no longer a pass"* is
stronger than what shipped: **silence is no longer a pass, and any sentence is.**

I am not proposing a mechanism — every one I can think of is the marker file with extra steps, and §3c
already rejected that class for the right reason. What closes it is a reviewer reading the reason, and
**`REVIEW.md` item 4 already binds that**: a trailer is an assertion in the diff's documentation, so
*"is every assertion actually read against the code?"* covers it without an eighth checklist item. Noted
here so the next reviewer knows the trailer is item-4 material and not a checkmark.
